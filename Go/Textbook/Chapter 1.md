# I. Введение в Go

Материал главы соответствует Go 1.27. Большая часть рассмотренных правил существует в языке давно, но версия важна для точного описания инструментов и более поздних возможностей Go.

## §1.1. Что такое Go

Go — компилируемый язык программирования общего назначения со статической типизацией и автоматическим управлением памятью. Его начали разрабатывать в Google в 2007 году; основными авторами языка были Роберт Гризмер, Роб Пайк и Кен Томпсон. Первая публичная версия появилась в 2009 году.

Go часто называют языком для микросервисов, но он не создавался специально только для них. Изначально разработчики хотели упростить работу с большими программными системами: ускорить сборку, сделать зависимости явными, предоставить удобные средства конкурентного программирования и сохранить язык достаточно простым, чтобы большой проект было легче читать и сопровождать.

Эти свойства оказались особенно полезны для серверных и сетевых приложений. Поэтому на Go часто пишут:

- веб-сервисы и микросервисы;
- сетевые серверы и прокси;
- облачную инфраструктуру;
- консольные утилиты;
- системы мониторинга и оркестрации;
- инструменты для разработчиков.

Однако область применения языка этим не ограничивается. На Go можно писать практически любые программы, для которых подходят его модель выполнения, стандартная библиотека и доступные сторонние пакеты.

### Основные свойства языка

**Статическая типизация.** Типы выражений и корректность большинства операций проверяются при компиляции. Например, число нельзя случайно сложить со строкой:

```go
package main

func main() {
	// result := 10 + "20" // ошибка компиляции: разные типы
}
```

**Компиляция в машинный код.** Обычная Go-программа заранее компилируется в исполняемый файл. Для её запуска, как правило, не требуется отдельно установленная виртуальная машина.

**Сборщик мусора.** Когда объект становится недостижимым, среда выполнения Go может повторно использовать занятую им память. Точный момент сборки языком не задаётся. Это не означает, что память бесконечна или что разработчику не нужно следить за лишними выделениями; язык лишь снимает необходимость вручную освобождать обычные объекты.

**Встроенная поддержка конкурентности.** В языке есть горутины и каналы. Они будут рассмотрены отдельно: наличие этих средств не делает программу автоматически параллельной, быстрой или защищённой от гонок данных.

**Небольшое ядро языка.** В Go сравнительно мало синтаксических конструкций. Многие привычные возможности предоставляются не отдельным синтаксисом, а обычными пакетами и инструментами.

**Единое форматирование.** Инструмент `gofmt` приводит исходный код к стандартному виду. В Go обычно не обсуждают, сколько пробелов поставить или где расположить фигурную скобку: принятый формат задаётся инструментом.

## §1.2. Компиляция и запуск программы

Минимальная исполняемая программа выглядит так:

```go
package main

import "fmt"

func main() {
	fmt.Println("Hello, Go!")
}
```

> Вывод: `Hello, Go!`

Здесь:

- `package main` указывает, что файл относится к исполняемому пакету `main`;
- `import "fmt"` подключает пакет стандартной библиотеки для форматированного ввода и вывода;
- `func main()` объявляет функцию, с которой начинается выполнение программы;
- `fmt.Println` вызывает экспортируемую функцию `Println` из пакета `fmt`.

В некоторых коротких фрагментах ниже используется встроенная функция `println`, чтобы не повторять импорт `fmt`. Она предназначена прежде всего для начальной загрузки системы и отладки, а формат её вывода зависит от реализации. В обычном прикладном коде для вывода используют `fmt.Print`, `fmt.Println`, `fmt.Printf` или другой подходящий пакет.

Функция `main` должна находиться в пакете `main`, не принимать аргументов и не возвращать результат. Аргументы командной строки получают через пакет `os`, а код завершения при необходимости задают с помощью `os.Exit`.

### `go run` и `go build`

Команда

```text
go run .
```

компилирует программу во временный исполняемый файл и запускает его. Это удобно во время разработки, но `go run` не является интерпретатором: перед запуском исходный код всё равно компилируется.

Команда

```text
go build
```

проверяет код, компилирует пакеты, связывает их и создаёт исполняемый файл для пакета `main`. Если собирается обычный библиотечный пакет, `go build` проверяет и компилирует его, но не оставляет рядом отдельный исполняемый файл.

При сборке происходит несколько логических этапов:

1. Проверяется синтаксис исходных файлов.
2. Выполняется проверка типов.
3. Компилируются необходимые пакеты.
4. Для исполняемой программы компоновщик собирает итоговый файл.

В исполняемый файл обычно включается необходимая часть среды выполнения Go: поддержка сборщика мусора, планировщика горутин и другие механизмы. При этом конкретный способ компоновки зависит от программы, платформы и параметров сборки. Например, использование `cgo` может добавить зависимость от системных библиотек.

### Ошибка компиляции и ошибка времени выполнения

Если нарушены правила языка, компилятор не создаст программу:

```go
package main

func main() {
	// var enabled bool = 1 // ошибка компиляции: 1 не является bool
}
```

Другие проблемы возникают только при выполнении:

```go
package main

func main() {
	x := 0
	_ = 10 / x // panic: деление целого числа на ноль
}
```

Компилятор видит, что `x` имеет подходящий целочисленный тип, поэтому сама операция разрешена. Конкретное значение переменной проверяется при выполнении, и деление на ноль вызывает `panic`.

`panic` — аварийное прекращение обычного хода выполнения текущей горутины с началом раскрутки стека. Это не то же самое, что ошибка компиляции. Подробно обработка `panic` будет рассмотрена позже.

Если написать константное деление на ноль, компилятор обнаружит проблему заранее:

```go
// const result = 10 / 0 // ошибка компиляции
```

### Кросс-компиляция

Компилятор Go умеет собирать программы для многих операционных систем и архитектур. Целевая платформа задаётся переменными окружения `GOOS` и `GOARCH`, например:

```text
GOOS=linux GOARCH=amd64 go build
```

Так можно на одной системе собрать файл для другой. Однако программа с `cgo` или платформозависимым кодом может потребовать дополнительные инструменты и настройки.

## §1.3. Пакеты, модули и библиотеки

### Пакет

Исходный код Go организован в пакеты. В обычном случае все `.go`-файлы одного каталога принадлежат одному пакету и компилируются вместе:

```go
package calculator
```

Функции, типы, переменные и константы, объявленные на уровне пакета в одном файле, доступны другим файлам того же пакета. Порядок файлов не задаёт порядок видимости: пакет рассматривается как единое целое.

Имя, начинающееся с заглавной буквы, экспортируется из пакета:

```go
package calculator

const Version = "1.0" // доступно другим пакетам
const precision = 2   // доступно только внутри calculator
```

Регистр является частью имени: `Version` и `version` — разные идентификаторы. Экспорт определяется именно первой Unicode-буквой имени, а не отдельным ключевым словом вроде `public`.

### Импорт пакета

Чтобы использовать другой пакет, его импортируют:

```go
package main

import (
	"fmt"
	"strings"
)

func main() {
	text := strings.ToUpper("go")
	fmt.Println(text)
}
```

> Вывод: `GO`.

Импортируемый пакет обычно используется через его имя: `strings.ToUpper`, `fmt.Println`. Это ясно показывает, откуда взята функция.

Локальное имя импорта можно изменить:

```go
import formatter "fmt"
```

После этого обращаться к пакету нужно как `formatter.Println`. Псевдоним бывает полезен при конфликте имён, но без причины переименовывать пакеты не следует. Имя, используемое в коде, задаётся объявлением самого пакета, а путь в `import` указывает, где этот пакет находится; последнее слово пути обычно совпадает с именем пакета, но язык не требует такого совпадения.

Импорт с именем `_` загружает пакет только ради побочных эффектов его инициализации:

```go
import _ "example.com/driver"
```

Обращаться к именам пакета после такого импорта нельзя. Пакет всё равно будет инициализирован: сначала вычислятся его пакетные переменные, затем выполнятся специальные функции `init`. Эта форма встречается, например, при регистрации драйверов и плагинов. Побочные импорты должны быть осознанными: по обычному импорту читателю проще увидеть реальную зависимость.

Точечный импорт помещает экспортируемые имена пакета прямо в текущую область видимости:

```go
import . "fmt"
```

После него можно написать `Println` без `fmt.`. Такая запись ухудшает понимание происхождения имён и может создавать конфликты, поэтому в обычном коде её почти всегда избегают.

Неиспользуемый импорт является ошибкой компиляции:

```go
package main

// import "strings" // ошибка, если пакет нигде не используется

func main() {}
```

Такая строгость не позволяет исходным файлам постепенно накапливать ненужные зависимости. Инструменты редактора и `goimports` обычно удаляют неиспользуемые импорты автоматически.

Пакеты не могут образовывать цикл зависимостей. Если пакет `a` импортирует `b`, а `b` прямо или через другие пакеты импортирует `a`, сборка завершится ошибкой. Это правило сохраняет граф зависимостей направленным и позволяет компилировать пакеты в понятном порядке.

Перед запуском `main` программа инициализирует все необходимые пакеты. Сначала инициализируются зависимости пакета, затем его собственные пакетные переменные и функции вида

```go
func init() {
	// подготовка состояния пакета
}
```

`init` нельзя вызвать явно. В пакете может быть несколько таких функций, но код не должен без необходимости зависеть от их сложного взаимного порядка: явная функция настройки обычно понятнее и удобнее для тестирования. Функция `main` запускается только после завершения инициализации всех импортированных пакетов.

### Стандартная библиотека

Вместе с Go поставляется стандартная библиотека. В ней есть пакеты для работы со строками, файлами, сетью, HTTP, JSON, временем, криптографией, тестированием и многими другими задачами.

Например:

```go
import "fmt"
import "net/http"
import "encoding/json"
```

Слово «библиотека» обычно обозначает набор готового кода, предназначенного для использования другими программами. В Go библиотека обычно представлена одним или несколькими пакетами. Однако в терминологии инструментов Go важнее точно различать пакет и модуль.

### Модуль

Модуль — версия набора связанных пакетов. Его корень содержит файл `go.mod`:

```text
module example.com/project

go 1.27
```

Первая строка задаёт путь модуля — префикс путей его пакетов. Строка `go` задаёт минимальную версию языка, семантику некоторых возможностей и поведение инструментов для этого модуля; она не означает, что в программу автоматически подключается отдельная библиотека с таким номером.

Новый модуль создают командой:

```text
go mod init example.com/project
```

Упрощённое соотношение понятий выглядит так:

- файл содержит исходный код;
- несколько файлов каталога образуют пакет;
- один или несколько пакетов входят в модуль;
- программа импортирует пакеты;
- модуль задаёт версии внешних модулей, из которых могут быть взяты импортируемые пакеты.

Модуль не обязан быть исполняемой программой. Он может содержать библиотечные пакеты, команды или и то и другое.

## §1.4. Простые типы

Тип определяет множество возможных значений и допустимые операции над ними. Go не выполняет произвольные неявные преобразования между числовыми типами: даже близкие по смыслу типы обычно нужно преобразовывать явно.

### Логический тип

Тип `bool` имеет два значения: `true` и `false`.

```go
var ready bool = true
var stopped bool // false
```

Нулевое значение `bool` — `false`. Числа не преобразуются в логические значения автоматически:

```go
// var ready bool = 1 // ошибка компиляции
// if 10 {            // ошибка компиляции: условие должно иметь тип bool
// }
```

В Go нет правила «ноль — ложь, всё остальное — истина». Условие должно быть логическим выражением.

### Целые типы

Знаковые целые типы:

- `int8`, `int16`, `int32`, `int64`;
- `int`.

Беззнаковые целые типы:

- `uint8`, `uint16`, `uint32`, `uint64`;
- `uint`;
- `uintptr`.

Число в имени фиксированного типа указывает размер в битах. Например, `int8` хранит значения от `-128` до `127`, а `uint8` — от `0` до `255`.

Размер `int` и `uint` зависит от целевой архитектуры: это 32 или 64 бита. При этом `int` и `int64` остаются разными типами даже на 64-битной системе:

```go
var x int = 10
var y int64 = 20

// var sum = x + y      // ошибка компиляции: разные типы
var sum = int64(x) + y // явное преобразование
```

> `sum` равно `30` и имеет тип `int64`.

Преобразование не проверяет, помещается ли исходное значение в новый целочисленный тип:

```go
var wide uint16 = 256
var narrow uint8 = uint8(wide)
```

После преобразования `narrow == 0`: сохраняются только младшие 8 бит. Это определённое поведение, а не случайный результат. Поэтому явная запись преобразования не означает, что оно безопасно по смыслу.

`uintptr` — беззнаковый целочисленный тип, достаточно большой для хранения битового представления указателя. Это всё ещё число, а не обычный указатель: сборщик мусора не обязан считать значение `uintptr` ссылкой на живой объект. Низкоуровневая работа с адресами требует отдельного разбора.

### `byte` и `rune`

`byte` — псевдоним типа `uint8`, а `rune` — псевдоним типа `int32`:

```go
var b byte = 65
var r rune = 'Я'
```

Псевдоним не создаёт новый тип. Поэтому `byte` и `uint8` полностью взаимозаменяемы, как и `rune` с `int32`.

Обычно `byte` используют, когда значение рассматривают как байт данных, а `rune` — когда оно обозначает кодовую точку Unicode. Символьный литерал в одинарных кавычках, например `'Я'`, имеет вид целочисленной константы, а не отдельного типа `char`.

### Числа с плавающей точкой

В Go есть типы `float32` и `float64`. Чаще используется `float64`, потому что обычная неявно типизированная вещественная константа при присваивании переменной получает именно этот тип:

```go
temperature := 21.5 // float64
```

Многие десятичные дроби невозможно точно представить в двоичной системе:

```go
package main

import "fmt"

func main() {
	x := 0.1 + 0.2
	fmt.Printf("%.20f\n", x)
}
```

> Вывод: `0.29999999999999998890`.

В данном примере выражение `0.1 + 0.2` сначала вычисляется как константа с высокой точностью, а затем один раз округляется при присваивании `float64`. Поэтому оно не полностью повторяет вычисление двух уже округлённых переменных:

```go
a := 0.1
b := 0.2
sum := a + b
```

Здесь `sum` обычно имеет представление, которое при печати с 20 знаками выглядит как `0.30000000000000004441`. В общем случае результаты вычислений с плавающей точкой нужно осторожно сравнивать на точное равенство.

Деление переменной с плавающей точкой на ноль не вызывает `panic`. По правилам IEEE 754 результатом может стать бесконечность или NaN — специальное значение «не число»:

```go
zero := 0.0
positiveInfinity := 1.0 / zero
notANumber := zero / zero
```

NaN не равен даже самому себе: `notANumber == notANumber` даст `false`. Сравнения NaN по порядку также дают `false`. Для явной проверки используют `math.IsNaN`. Константное выражение `1.0 / 0.0` по-прежнему является ошибкой компиляции: правило IEEE 754 применяется здесь к значениям переменных во время выполнения.

У `float32` заметно меньше точность, чем у `float64`. Преобразование `float64` в `float32` может потерять часть значения.

### Комплексные числа

Типы `complex64` и `complex128` хранят комплексные числа. Их компоненты имеют типы `float32` и `float64` соответственно:

```go
z := complex(2.0, 3.0)
realPart := real(z)
imaginaryPart := imag(z)
```

Для комплексных чисел доступны арифметические операции и сравнение на равенство, но нет упорядочивающих сравнений `<`, `>` и подобных: для комплексных чисел не задан естественный линейный порядок.

### Строки

Тип `string` представляет неизменяемую последовательность байт:

```go
text := "Go"
```

Строка может содержать текст в UTF-8, и строковые литералы в исходном коде обычно именно так его кодируют, но сам тип `string` не требует, чтобы каждый набор байт был корректным UTF-8.

`len` возвращает количество байт, а не количество символов:

```go
package main

import "fmt"

func main() {
	fmt.Println(len("Go"))
	fmt.Println(len("Я"))
}
```

> Вывод: сначала `2`, затем `2`. Буква `Я` занимает два байта в UTF-8.

Байт строки можно прочитать по индексу, но нельзя изменить:

```go
text := "Go"
first := text[0] // byte со значением 'G'

_ = first
// text[0] = 'N' // ошибка компиляции: строки неизменяемы
```

Строки можно сравнивать и соединять оператором `+`:

```go
language := "G" + "o"
same := language == "Go"
```

### Литералы

Литерал записывает значение непосредственно в исходном коде. Целые числа можно записывать в нескольких системах счисления:

```go
decimal := 42      // десятичная
binary := 0b101010 // двоичная
octal := 0o52      // восьмеричная
hex := 0x2A        // шестнадцатеричная
```

Все четыре значения равны `42`. Регистр букв в префиксе и шестнадцатеричных цифрах значения не меняет.

Символ `_` можно использовать как визуальный разделитель цифр:

```go
population := 1_000_000
mask := 0b1111_0000
```

Разделитель не влияет на значение, но ставить его можно не в любом месте: литерал должен соответствовать синтаксису языка.

Для вещественных значений доступны десятичная точка и показатель степени:

```go
distance := 12.5
small := 1.5e-3 // 0.0015
```

Интерпретируемая строка записывается в двойных кавычках и обрабатывает escape-последовательности:

```go
line := "first\nsecond"
quote := "\"Go\""
```

Raw-строка записывается в обратных кавычках. В ней обратная косая черта не начинает escape-последовательность, а переводы строк сохраняются:

```go
path := `C:\temp\file.txt`
multiline := `first
second`
```

Символьные литералы используют одинарные кавычки и обозначают одну Unicode-кодовую точку:

```go
latin := 'A'
cyrillic := 'Я'
newline := '\n'
```

Это целочисленные константы. Запись `'AB'` недопустима, потому что содержит больше одной кодовой точки.

### Нулевые значения

Если переменная объявлена без начального значения, Go инициализирует её нулевым значением типа:

```go
var count int       // 0
var ratio float64   // 0
var enabled bool    // false
var name string     // ""
var number complex64 // 0 + 0i
```

В Go нет обычной неинициализированной локальной переменной со случайным содержимым. Объявленная переменная всегда получает определённое значение.

Нулевое значение не обязательно означает, что объект уже готов к любому осмысленному использованию. Для одних типов оно специально сделано полезным, а для других может означать отсутствие настроенного состояния. Это зависит от конкретного типа.

## §1.5. Переменные и константы

### Объявление через `var`

Полная форма явно задаёт тип и значение:

```go
var count int = 10
```

Если значение не указано, используется нулевое значение:

```go
var count int // 0
```

Если значение есть, тип часто можно вывести:

```go
var count = 10       // int
var message = "hello" // string
```

Несколько переменных можно объявить вместе:

```go
var x, y int = 10, 20
var width, height = 1920, 1080
```

Группа объявлений удобна на уровне пакета или для связанных значений:

```go
var (
	host = "localhost"
	port = 8080
	debug bool
)
```

Выражения справа вычисляются до присваивания результатов переменным слева. Поэтому значения можно обменять без временной переменной:

```go
x, y := 10, 20
x, y = y, x
```

После присваивания `x == 20`, а `y == 10`. Сначала берутся прежние значения `y` и `x`, затем они присваиваются слева.

### Короткое объявление `:=`

Внутри функции часто используется короткая форма:

```go
count := 10
message := "hello"
```

Она эквивалентна объявлению `var` с выводом типа. За пределами функций `:=` использовать нельзя.

`:=` именно объявляет хотя бы одну новую переменную. Если все имена уже существуют в том же блоке, нужно обычное присваивание:

```go
x := 10
x = 20
// x := 30 // ошибка компиляции: слева нет новой переменной
```

В составном объявлении часть имён может уже существовать, но хотя бы одно непропущенное имя должно быть новым:

```go
x := 10
x, y := 20, 30
```

Здесь `x` не объявляется заново: ему присваивается `20`. Переменная `y` объявляется впервые. Это разрешено, потому что оба имени находятся в одном блоке и среди них есть новое.

Вложенный блок меняет ситуацию:

```go
x := 10

if true {
	x := 20
	println(x)
}

println(x)
```

> Вывод: сначала `20`, затем `10`.

Внутреннее `x := 20` создаёт новую переменную, которая временно скрывает внешнюю. Это называется затенением. Код компилируется, но изменение внутренней переменной никак не меняет внешнюю.

Затенение особенно опасно в длинных функциях и при работе с ошибками: строка, похожая на присваивание, может создать новую переменную в более узкой области видимости.

### Область видимости

Переменная, объявленная внутри функции, доступна начиная после завершения её объявления и до конца самого внутреннего блока, содержащего объявление:

```go
func main() {
	count := 10

	{
		message := "inside"
		println(count, message)
	}

	// println(message) // ошибка: message уже вне области видимости
}
```

В отличие от C++, имя локальной переменной не доступно в её собственном инициализаторе:

```go
func main() {
	// x := x // ошибка компиляции, если внешнего x нет
}
```

Область видимости `x` начинается после короткого объявления. Если существует внешняя переменная `x`, правая часть увидит именно её:

```go
package main

var x = 10

func main() {
	x := x + 1
	println(x)
}
```

> Вывод: `11`. В правой части используется пакетная переменная, а после объявления локальная `x` скрывает её.

### Неиспользуемые переменные и пустой идентификатор

Локальная переменная должна быть использована:

```go
func main() {
	// value := 10 // ошибка компиляции: value объявлена и не используется
}
```

Переменные уровня пакета могут оставаться неиспользованными. Такое различие позволяет хранить пакетное состояние и одновременно не допускает лишних локальных вычислений.

Имя `_` называется пустым идентификатором. Присвоенное ему значение отбрасывается:

```go
value := 10
_ = value
```

`_` не является обычной переменной: прочитать из него значение нельзя. Несколько записей `_` не обозначают один общий объект.

Пустой идентификатор полезен, когда выражение возвращает несколько результатов, а нужен только один. Не стоит использовать `_` только для постоянного сокрытия ненужного кода — чаще такой код следует удалить.

### Константы

Константа объявляется словом `const`:

```go
const maxAttempts = 3
const greeting string = "hello"
```

Значение константы должно быть вычислимо при компиляции. Его нельзя изменить:

```go
// maxAttempts = 4 // ошибка компиляции
```

Числовая константа без явно указанного типа может иметь точное значение, ещё не ограниченное размером машинного типа:

```go
const huge = 1 << 100
```

Само объявление корректно. Ошибка появится, если попытаться поместить значение в тип, где оно не представимо:

```go
// var x int64 = huge // ошибка компиляции: переполнение
```

Нетипизированная константа получает конкретный тип, когда этого требует контекст. Если контекста нет, используются типы по умолчанию: `bool`, `rune`, `int`, `float64`, `complex128` или `string` в зависимости от вида константы.

Это объясняет, почему выражение ниже допустимо, хотя обычные переменные `int` и `float64` нельзя свободно складывать:

```go
var x float64 = 1.5
var y = x + 2
```

Константа `2` представима как `float64` и получает подходящий тип из контекста. Если вместо неё использовать переменную типа `int`, потребуется явное преобразование.

## §1.6. Операции

### Арифметические операции

Для чисел используются операторы:

- `+` — сложение;
- `-` — вычитание;
- `*` — умножение;
- `/` — деление;
- `%` — остаток от целочисленного деления.

Тип операндов влияет на результат:

```go
integerResult := 7 / 2
floatingResult := 7.0 / 2.0
```

`integerResult == 3`, потому что оба операнда после получения типа являются целыми. `floatingResult == 3.5`, потому что выражение представляется числом с плавающей точкой.

Унарные `+` и `-` применяются к одному числу:

```go
x := 10
positive := +x
negative := -x
```

В Go нет отдельного оператора возведения в степень. Для вещественных чисел используют функцию `math.Pow`, а для целых часто применяют подходящий алгоритм или последовательное умножение.

Для знаковых целых деление усекает результат по направлению к нулю:

```go
a := 7 / 3   // 2
b := -7 / 3  // -2
c := 7 / -3  // -2
```

Остаток удовлетворяет равенству `x = q*y + r`, где `q` — результат деления с усечением:

```go
r := -7 % 3 // -1
```

Оператор `%` не применяется к `float32`, `float64` и комплексным числам.

Есть один граничный случай для знаковых целых. Если самое маленькое значение типа разделить на `-1`, положительный математический результат не поместится в тот же тип. Go определяет результат как исходное минимальное значение, а остаток — как ноль:

```go
var x int8 = -128
quotient := x / -1  // -128
remainder := x % -1 // 0
```

Это следствие определённых правил целочисленного переполнения Go, а не `panic` и не неопределённое поведение.

### Переполнение целых чисел

Для беззнакового типа арифметика выполняется по модулю `2ⁿ`, где `n` — количество бит:

```go
var x uint8 = 255
x++
```

После увеличения `x == 0`.

Знаковые целые операции тоже могут переполняться. Для конкретного знакового типа результат определяется его представлением, и программа продолжает выполняться. В отличие от C++, знаковое переполнение целого числа в Go не является неопределённым поведением, а компилятор не может считать, что оно никогда не происходит.

```go
var x int8 = 127
x++
```

После увеличения `x == -128`.

Если переполняется константа при приведении к требуемому типу, возникает ошибка компиляции:

```go
// const x int8 = 128 // ошибка: 128 не представимо как int8
```

### Присваивание и составные операции

Присваивание записывается через `=`:

```go
x := 10
x = 20
```

Составные операции одновременно вычисляют и присваивают результат:

```go
x += 5
x *= 2
x %= 7
```

Операции `++` и `--` существуют только как отдельные инструкции:

```go
x++
x--
```

Они не являются выражениями и ничего не возвращают:

```go
// y := x++ // ошибка компиляции
// ++x      // ошибка: префиксной формы нет
```

Это убирает выражения, в которых значение изменяется внутри более крупного вычисления и результат зависит от трудно читаемого порядка действий.

### Сравнения

Операторы сравнения:

- `==` и `!=` — равенство и неравенство;
- `<`, `<=`, `>` и `>=` — сравнение порядка.

Результат сравнения всегда имеет тип `bool`:

```go
age := 20
adult := age >= 18
```

Целые числа, числа с плавающей точкой и строки можно сравнивать по порядку. Строки сравниваются лексикографически по байтам. Логические и комплексные значения можно сравнить на равенство, но нельзя упорядочить.

Операнды должны иметь совместимые типы. Go не станет автоматически преобразовывать `int` в `int64` только ради сравнения:

```go
var x int = 10
var y int64 = 10

// same := x == y      // ошибка компиляции
same := int64(x) == y // true
```

### Логические операции и короткое вычисление

Для логических значений используются:

- `!condition` — отрицание;
- `left && right` — логическое И;
- `left || right` — логическое ИЛИ.

`&&` и `||` вычисляются слева направо и используют короткое вычисление:

- у `left && right` правая часть вычисляется только тогда, когда левая равна `true`;
- у `left || right` правая часть вычисляется только тогда, когда левая равна `false`.

Это позволяет сначала проверить условие безопасности:

```go
divisor := 0

if divisor != 0 && 100/divisor > 2 {
	println("large quotient")
}
```

Деление не выполняется, потому что `divisor != 0` равно `false`. Поэтому `panic` не возникает.

Порядок условий важен:

```go
// if 100/divisor > 2 && divisor != 0 {
//     println("large quotient")
// }
```

В таком варианте опасная операция стоит первой и будет выполнена до проверки делителя.

### Побитовые операции

Для целых чисел доступны:

- `&` — побитовое И;
- `|` — побитовое ИЛИ;
- `^` — побитовое исключающее ИЛИ;
- `&^` — сброс битов;
- `<<` — сдвиг влево;
- `>>` — сдвиг вправо.

Пример со флагами:

```go
const (
	readPermission  = 1 << 0 // 001
	writePermission = 1 << 1 // 010
	execPermission  = 1 << 2 // 100
)

permissions := readPermission | writePermission
canWrite := permissions&writePermission != 0
permissions &^= writePermission
```

Сначала `permissions` содержит флаги чтения и записи. Проверка через `&` показывает, установлен ли бит записи. Оператор `&^` затем сбрасывает этот бит.

Унарный оператор `^` инвертирует каждый бит целого значения:

```go
var value uint8 = 0b0000_1111
inverted := ^value // 1111_0000
```

Один и тот же символ `^` означает инверсию с одним операндом и исключающее ИЛИ с двумя операндами.

Количество позиций сдвига должно быть неотрицательным целым значением. У сдвигов нет правила «автоматически взять остаток по ширине типа»: большой сдвиг допустим, но значащие биты могут полностью выйти за границы конечного целого типа.

Сдвиг вправо беззнакового числа добавляет нулевые биты слева. Для отрицательного знакового числа результат соответствует делению на степень двойки с округлением вниз, поэтому слева фактически сохраняются единичные биты знака.

Если отрицательный сдвиг известен как константа, это ошибка компиляции. Если отрицательное значение появляется только при выполнении, операция вызывает `panic`.

### Приоритет операций

Операции более высокого приоритета выполняются раньше. Например, умножение выполняется раньше сложения:

```go
result := 2 + 3*4 // 14
```

Скобки позволяют явно задать порядок:

```go
result := (2 + 3) * 4 // 20
```

Даже когда скобки формально не нужны, они полезны в длинном условии, если делают смысл очевиднее. Не следует заставлять читателя вспоминать всю таблицу приоритетов ради понимания бизнес-условия.

## §1.7. Условный оператор `if`

Базовая форма:

```go
temperature := 25

if temperature > 20 {
	println("warm")
}
```

Круглые скобки вокруг условия не требуются, а фигурные скобки обязательны. Условие должно иметь тип `bool`.

### `else` и `else if`

```go
score := 82

if score >= 90 {
	println("excellent")
} else if score >= 60 {
	println("passed")
} else {
	println("failed")
}
```

> Вывод: `passed`.

Условия проверяются сверху вниз. После первого истинного условия остальные ветви не рассматриваются.

`else` записывается на той же строке, что и закрывающая скобка предыдущей ветви. В Go перевод строки может автоматически вставить точку с запятой после `}`, поэтому перенос `else` на новую строку изменит разбор программы и приведёт к синтаксической ошибке.

### Сложные условия

```go
age := 25
hasLicense := true
isBanned := false

if age >= 18 && hasLicense && !isBanned {
	println("access granted")
}
```

Сложное условие остаётся обычным выражением типа `bool`. Его части лучше располагать в порядке от дешёвых и безопасных проверок к тем, которые имеют смысл только после предыдущих.

```go
name := "Go"

if len(name) > 0 && name[0] == 'G' {
	println("starts with G")
}
```

Проверка длины выполняется первой. Если строка пуста, обращение `name[0]` будет пропущено и выхода за границы не произойдёт.

При смешивании `&&` и `||` полезно ставить скобки:

```go
if (isAdmin || isOwner) && !isBlocked {
	println("allowed")
}
```

Без скобок `&&` имеет более высокий приоритет, чем `||`. Запись со скобками не только задаёт нужную группировку, но и явно показывает её читателю.

### Начальная инструкция в `if`

Перед условием можно выполнить короткую инструкцию, отделив её точкой с запятой:

```go
if length := len("hello"); length > 3 {
	println(length)
}
```

> Вывод: `5`.

Переменная `length` доступна в условии, в ветви `if` и во всех связанных ветвях `else`, но не после всего условного оператора:

```go
if value := 10; value > 20 {
	println("large", value)
} else {
	println("small", value)
}

// println(value) // ошибка: value вне области видимости
```

Эта форма часто используется, когда промежуточное значение нужно только для проверки и обработки результата. Она сокращает область видимости переменной и не позволяет случайно использовать её позже.

В начальной части разрешена простая инструкция, а не произвольный список команд. Чаще всего там находится короткое объявление.

### В Go нет тернарного оператора

Конструкции `condition ? a : b` в Go нет. Нужно использовать обычный `if`:

```go
max := x
if y > max {
	max = y
}
```

Это намеренное упрощение языка: выбор значения остаётся обычным управляющим кодом, а не выражением, вложенным в другое выражение.

## §1.8. Цикл `for`

В Go есть одно ключевое слово для циклов — `for`. Оно покрывает обычный цикл со счётчиком, аналог `while` и бесконечный цикл.

### Цикл со счётчиком

```go
for i := 0; i < 5; i++ {
	println(i)
}
```

> Выводятся числа от `0` до `4`.

Здесь:

1. `i := 0` выполняется один раз перед началом цикла.
2. `i < 5` проверяется перед каждой итерацией.
3. Тело выполняется, если условие истинно.
4. `i++` выполняется после тела.
5. Затем условие проверяется снова.

Первая и третья части являются простыми инструкциями, а средняя — логическим условием. В первой части можно использовать `:=`, но в завершающей части короткое объявление запрещено. Обычно там находится присваивание, вызов функции, операция отправки в канал или `i++`/`i--`.

Переменная `i` принадлежит области видимости цикла и недоступна после него:

```go
for i := 0; i < 3; i++ {
	println(i)
}

// println(i) // ошибка компиляции
```

Любую из трёх частей можно опустить:

```go
i := 0
for ; i < 3; {
	println(i)
	i++
}
```

Однако если остаётся только условие, принято использовать более короткую форму.

### Аналог `while`

Отдельного ключевого слова `while` в Go нет:

```go
count := 3

for count > 0 {
	println(count)
	count--
}
```

Цикл продолжает работу, пока условие равно `true`. Условие проверяется до каждой итерации, поэтому тело может не выполниться ни разу.

Отдельного цикла `do while`, который обязательно выполняет тело хотя бы один раз, тоже нет. Его можно выразить бесконечным циклом с проверкой в конце:

```go
shouldContinue := false

for {
	println("body runs first")

	if !shouldContinue {
		break
	}
}
```

Тело выполняется до первой проверки, после чего `break` при необходимости завершает цикл. В примере оно выполнится ровно один раз.

### Бесконечный цикл

Если условие отсутствует, оно считается истинным:

```go
for {
	println("repeat")
	break
}
```

Такая форма используется в серверных циклах, при чтении потока событий и в случаях, когда условие выхода удобнее проверять внутри тела.

Бесконечный `for` без достижимого выхода считается завершающей инструкцией с точки зрения анализа функции. Но наличие `break`, относящегося к этому циклу, означает, что выполнение потенциально может продолжиться после него.

### `break`

Без метки `break` завершает ближайшую содержащую его конструкцию `for`, `switch` или `select`. В рассматриваемых здесь примерах такой конструкцией является ближайший цикл `for`:

```go
for i := 0; i < 10; i++ {
	if i == 3 {
		break
	}
	println(i)
}
```

> Выводятся `0`, `1` и `2`. При `i == 3` цикл заканчивается до вызова `println`.

Вложенный `break` без метки завершает только внутренний цикл:

```go
for row := 0; row < 3; row++ {
	for column := 0; column < 3; column++ {
		if column == 1 {
			break
		}
		println(row, column)
	}
}
```

Для каждой строки внутренний цикл успеет вывести только столбец `0`. Внешний цикл продолжит работу.

### `continue`

`continue` завершает текущую итерацию и переходит к следующей:

```go
for i := 0; i < 5; i++ {
	if i%2 == 0 {
		continue
	}
	println(i)
}
```

> Выводятся `1` и `3`.

В цикле со счётчиком после `continue` выполняется завершающая инструкция цикла — здесь `i++` — и только затем снова проверяется условие.

В цикле, похожем на `while`, обновление переменной часто находится в теле. Нужно сделать его до `continue`, иначе можно получить бесконечный цикл:

```go
i := 0
for i < 5 {
	i++
	if i%2 == 0 {
		continue
	}
	println(i)
}
```

Если перенести `i++` в конец тела, то при первом подходящем для `continue` значении обновление будет пропущено и условие перестанет изменяться.

### Метки для вложенных циклов

Метка позволяет явно указать, какой внешний цикл нужно завершить:

```go
Outer:
for row := 0; row < 3; row++ {
	for column := 0; column < 3; column++ {
		if row == 1 && column == 1 {
			break Outer
		}
		println(row, column)
	}
}
```

`break Outer` завершает сразу внешний цикл. Без метки завершился бы только внутренний.

Для `continue` метка должна обозначать внешний цикл:

```go
Rows:
for row := 0; row < 3; row++ {
	for column := 0; column < 3; column++ {
		if column == 1 {
			continue Rows
		}
		println(row, column)
	}
}
```

После `continue Rows` начинается следующая итерация внешнего цикла. Его завершающая инструкция `row++` не пропускается.

Метки полезны для выхода из нескольких уровней, но большое количество меток обычно говорит о слишком сложной структуре функции. Иногда понятнее вынести поиск или обработку в отдельную функцию и выйти из неё через `return`.

### `return` как выход из цикла и функции

`break` завершает цикл, после чего функция продолжает работу. `return` завершает всю функцию:

```go
func findFirstPositive() int {
	for i := -3; i < 10; i++ {
		if i > 0 {
			return i
		}
	}

	return 0
}
```

Как только найдено подходящее значение, дальнейшие итерации и весь оставшийся путь до конца функции не выполняются. Если нужно лишь прекратить цикл, а затем продолжить функцию, следует использовать `break`.

### Типичные ошибки в циклах

**Условие никогда не становится ложным:**

```go
i := 0
for i < 3 {
	println(i)
	// i не изменяется — цикл бесконечный
}
```

**Ошибка на единицу:**

```go
for i := 0; i <= 3; i++ {
	println(i)
}
```

Этот цикл выполняется четыре раза и выводит `0`, `1`, `2`, `3`. Если нужны ровно три значения начиная с нуля, условие должно быть `i < 3`.

**Неверное ожидание от `break`:**

```go
for outer := 0; outer < 3; outer++ {
	for inner := 0; inner < 3; inner++ {
		break
	}
	println(outer)
}
```

`break` не завершает оба цикла. Внутренний цикл сразу заканчивается, но внешний выполняет все три итерации.

**Изменение счётчика и в заголовке, и в теле:**

```go
for i := 0; i < 10; i++ {
	i++
	println(i)
}
```

Счётчик увеличивается дважды за одну итерацию: один раз в теле и один раз завершающей инструкцией. Код корректен, но легко приводит к пропуску значений и обычно хуже читается.

Цикл `for range`, предназначенный для обхода строк, массивов, срезов, отображений, каналов, целых значений и функций-итераторов, будет рассмотрен вместе с соответствующими типами. Его правила зависят от того, что именно обходится, поэтому преждевременное обобщение часто приводит к ошибкам.
