## Глава 1. Введение

### 1.1 Пакеты и модули

В мире Go пакет (`package`) — это способ организации и структурирования кода. Он позволяет разделить код на логические блоки и группировать функции, переменные и другие элементы программы для удобства управления и повторного использования. Пакет в Go представляет собой каталог, в котором хранятся файлы с кодом, и каждый пакет имеет своё уникальное имя.

Пакет — это как организованная папка, в которой находятся связанные между собой элементы. Внутри одного пакета переменные, функции, структуры и другие элементы программы могут легко обмениваться данными и взаимодействовать друг с другом.

Так, например, если внутри пакета `car` будут находиться файлы `tyres` и `engine`, вполне возможно перед запуском двигателя проверить, что шины в порядке.

Каждый файл с исходным кодом обязан начинаться с объявления пакета, которому он принадлежит:

```go
package car
```

Специальный пакет `main` обозначает исполняемый файл (программу), а не библиотеку. В пакете `main` обязательно должна присутствовать функция `func main()` — точка входа в программу. Если объявить пакет как `main`, но не написать функцию `main`, произойдёт ошибка компиляции.

#### Экспортируемые и неэкспортируемые элементы

Внутри любого пакета могут быть экспортируемые и неэкспортируемые элементы — это важное различие, которое стоит учесть.

- **Экспортируемые элементы** — доступны для использования извне пакета (то есть элементы одного пакета будут доступны в других пакетах). Они начинаются с заглавной буквы. Чтобы их вызвать, необходимо написать название пакета и через точку — название элемента: `fmt.Println`.
- **Неэкспортируемые элементы** — доступны только внутри текущего пакета и начинаются со строчной буквы. Это могут быть переменные, функции, структуры и так далее. Они являются приватными для внешнего мира и недоступны за пределами текущего пакета.

Важный краевой случай: правило экспорта распространяется не только на функции и переменные верхнего уровня, но и на **поля структур**. Если структура экспортируется (имя с заглавной буквы), но одно из её полей названо со строчной буквы, то само поле останется недоступным для других пакетов — им нельзя будет ни прочитать, ни записать значение напрямую, даже зная о существовании структуры.

#### Модули

Модуль (`module`) — это единица версионирования и распространения кода в Go, объединяющая набор пакетов. Модуль описывается файлом `go.mod`, в котором указаны имя модуля, версия языка Go и список зависимостей с их версиями. Модуль создаётся командой:

```bash
go mod init example.com/myproject
```

Пакеты внутри одного модуля могут импортировать друг друга по пути относительно имени модуля, а сторонние зависимости подключаются через `go get` и фиксируются в `go.mod` и `go.sum` (файл с контрольными суммами для проверки целостности загруженного кода).

### 1.2 Основные типы данных

Go — язык со статической типизацией: тип переменной определяется на этапе компиляции и не может измениться в процессе выполнения.

#### Числовые типы

- Целые числа: `int`, `int8`, `int16`, `int32`, `int64` и их беззнаковые аналоги `uint`, `uint8` (он же `byte`), `uint16`, `uint32`, `uint64`. Тип `int` имеет размер, зависящий от платформы (32 или 64 бита), поэтому его точный размер на этапе написания кода не гарантирован — если важна точная разрядность, используют `int32`/`int64` явно.
- Числа с плавающей точкой: `float32`, `float64`.
- Комплексные числа: `complex64`, `complex128` (используются редко).

Важный краевой случай: Go **не выполняет неявных преобразований** между числовыми типами, даже между `int` и `int64` или между `int` и `float64`. Присваивание `var x int32 = 5; var y int64 = x` вызовет ошибку компиляции — необходимо явное приведение: `var y int64 = int64(x)`. Это сделано осознанно, чтобы избежать скрытой потери точности или переполнения.

#### Строки

Тип `string` — это неизменяемая (immutable) последовательность байт, обычно интерпретируемая как текст в кодировке UTF-8. Строку нельзя изменить «на месте»:

```go
s := "hello"
s[0] = 'H' // ошибка компиляции: cannot assign to s[0]
```

Обращение по индексу `s[i]` возвращает **байт**, а не символ (`rune`) — для строк, содержащих не-ASCII символы (например, кириллицу), это означает, что `len(s)` вернёт число байт, а не число видимых символов, и `s[i]` может вернуть часть многобайтового символа, а не целый символ. Для посимвольного перебора с учётом многобайтовых кодировок используется `range`:

```go
for i, r := range "привет" {
    fmt.Println(i, r) // r — это rune (int32), i — индекс байта, а не символа
}
```

#### Логический тип

`bool` — принимает значения `true` или `false`. В отличие от C/C++, в Go **нельзя** неявно использовать числа или указатели как булевы значения — конструкция вида `if x {}`, где `x` — число, вызовет ошибку компиляции. Условие обязано быть выражением именно типа `bool`.

#### Нулевые значения

У любого типа в Go есть нулевое значение по умолчанию, которое присваивается переменной при объявлении без явной инициализации: `0` для чисел, `""` для строк, `false` для bool. Неинициализированной памяти с «мусором», как в C, в Go не существует.

### 1.3 Условные операторы

#### if / else

```go
if x > 0 {
    fmt.Println("положительное")
} else if x < 0 {
    fmt.Println("отрицательное")
} else {
    fmt.Println("ноль")
}
```

Особенность Go: условие после `if` **не заключается в скобки**, а фигурные скобки обязательны, даже если тело состоит из одной строки. Кроме того, `if` поддерживает короткую инструкцию инициализации перед условием:

```go
if err := doSomething(); err != nil {
    fmt.Println("ошибка:", err)
}
```

Переменная `err`, объявленная таким образом, видна только внутри блока `if` (и последующих `else if`/`else`), что позволяет не засорять внешнюю область видимости — это часто используемая идиома при обработке ошибок.

#### switch

```go
switch day {
case "Пн", "Вт", "Ср", "Чт", "Пт":
    fmt.Println("будний день")
case "Сб", "Вс":
    fmt.Println("выходной")
default:
    fmt.Println("неизвестно")
}
```

Ключевые особенности `switch` в Go по сравнению с C/C++:

- **Нет проваливания (fallthrough) по умолчанию** — после выполнения одного `case` управление автоматически выходит из `switch`, `break` писать не нужно (и это не ошибка — просто избыточно). Если проваливание всё же нужно, его нужно указать явно ключевым словом `fallthrough` в конце блока `case`.
- В один `case` можно перечислить сразу несколько значений через запятую (как в примере выше).
- `switch` может использоваться **без выражения вообще** — тогда он превращается в удобную замену цепочки `if-else if`:

```go
switch {
case x > 0:
    fmt.Println("положительное")
case x < 0:
    fmt.Println("отрицательное")
default:
    fmt.Println("ноль")
}
```

- Как и `if`, `switch` поддерживает инструкцию инициализации: `switch x := compute(); x { ... }`.
- Отдельный вид — **type switch**, применяемый к значениям интерфейсного типа для определения конкретного типа, хранящегося внутри (см. Главу 2, раздел про интерфейсы).

### 1.4 Циклы

В Go существует **только один** циклический оператор — `for`, но он умеет работать в нескольких формах, заменяя `while` и `do-while` из других языков.

**Классическая форма (аналог C-style for):**

```go
for i := 0; i < 10; i++ {
    fmt.Println(i)
}
```

**Форма, аналогичная while:**

```go
i := 0
for i < 10 {
    fmt.Println(i)
    i++
}
```

**Бесконечный цикл:**

```go
for {
    // выполняется, пока не встретится break
}
```

**Цикл по коллекции — for range:**

```go
nums := []int{10, 20, 30}
for index, value := range nums {
    fmt.Println(index, value)
}
```

Важные краевые случаи `for range`:

- Для слайса/массива `range` возвращает индекс и **копию** значения элемента. Изменение переменной `value` внутри цикла **не изменит** исходный слайс:

```go
nums := []int{1, 2, 3}
for _, v := range nums {
    v *= 10 // изменяет только локальную копию v
}
fmt.Println(nums) // [1 2 3] — без изменений
```

Чтобы изменить сам слайс, нужно обращаться по индексу: `nums[i] *= 10`.

- Для `map` порядок итерации **не гарантирован** и может отличаться от запуска к запуску — на него нельзя полагаться.
- Для строки `range` возвращает индекс байта и `rune` (см. раздел про строки выше) — то есть корректно обрабатывает многобайтовые символы UTF-8, в отличие от прямого обращения по индексу.
- Если значение элемента не нужно, используется `_` (пустой идентификатор): `for i := range nums`.

**Управляющие конструкции:** `break` — досрочный выход из цикла, `continue` — переход к следующей итерации. Обе конструкции поддерживают **метки** (labels) для управления вложенными циклами:

```go
outer:
for i := 0; i < 3; i++ {
    for j := 0; j < 3; j++ {
        if j == 1 {
            continue outer // переходит к следующей итерации ВНЕШНЕГО цикла
        }
        fmt.Println(i, j)
    }
}
```

Без метки `continue`/`break` всегда относятся только к самому внутреннему циклу, в котором находятся.

### 1.5 Функции

Базовый синтаксис функции:

```go
func add(a int, b int) int {
    return a + b
}
```

Если несколько соседних параметров имеют одинаковый тип, тип можно указать один раз: `func add(a, b int) int`.

#### Множественный возврат значений

Функция в Go может возвращать несколько значений одновременно — эта особенность активно используется для возврата результата вместе с ошибкой:

```go
func divide(a, b int) (int, error) {
    if b == 0 {
        return 0, errors.New("деление на ноль")
    }
    return a / b, nil
}
```

#### Именованные возвращаемые значения

Возвращаемые значения можно именовать прямо в сигнатуре функции:

```go
func divide(a, b int) (result int, err error) {
    if b == 0 {
        err = errors.New("деление на ноль")
        return // naked return — вернёт текущие result и err
    }
    result = a / b
    return
}
```

Именованные возвращаемые значения автоматически инициализируются нулевыми значениями своих типов и позволяют использовать **naked return** — `return` без аргументов, при котором возвращаются текущие значения именованных переменных.

Важный краевой случай: если внутри функции значения присваиваются **другим** локальным переменным (не тем, что объявлены в сигнатуре), naked return всё равно вернёт именно именованные переменные из сигнатуры — то есть их нулевые значения, если они не были явно изменены. Это не ошибка компиляции, а логическая ошибка, которую легко упустить при чтении кода:

```go
func divide(a, b int) (result int, err error) {
    if b == 0 {
        e := errors.New("деление на ноль") // другая переменная!
        return // вернёт result=0, err=nil, а НЕ e
    }
    r := a / b // другая переменная!
    return // вернёт result=0 (не r), err=nil
}
```

#### Вариативные функции

Функция может принимать переменное число аргументов одного типа с помощью многоточия:

```go
func sum(nums ...int) int {
    total := 0
    for _, n := range nums {
        total += n
    }
    return total
}

sum(1, 2, 3)       // ОК
sum()              // ОК, nums == nil
existing := []int{1, 2, 3}
sum(existing...)   // передача слайса как набора аргументов
```

#### Функции как значения и анонимные функции

Функции в Go — значения первого класса: их можно сохранять в переменные, передавать как аргументы и возвращать из других функций.

```go
sum := func(a, b int) int {
    return a + b
}
fmt.Println(sum(3, 4))
```

Анонимные функции могут образовывать **замыкания (closures)** — захватывать переменные из окружающей области видимости и работать с ними даже после завершения внешней функции:

```go
func counter() func() int {
    count := 0
    return func() int {
        count++
        return count
    }
}

next := counter()
fmt.Println(next()) // 1
fmt.Println(next()) // 2
```

Это ключевое отличие анонимной функции от именованной верхнеуровневой: именованная функция не имеет доступа к локальным переменным вызывающего кода, а анонимная функция при замыкании — имеет.

#### defer

Конструкция `defer` откладывает выполнение вызова функции до момента выхода из окружающей функции (независимо от того, как произошёл выход — через `return` или через панику). Часто используется для освобождения ресурсов:

```go
f, _ := os.Open("file.txt")
defer f.Close()
```

Важный краевой случай: аргументы отложенного вызова **вычисляются в момент объявления `defer`**, а не в момент фактического выполнения:

```go
x := 1
defer fmt.Println(x) // зафиксирует x=1 прямо сейчас
x = 2
// в момент завершения функции выведется "1", а не "2"
```

Если объявлено несколько `defer`, они выполняются в порядке, обратном объявлению (по принципу стека, LIFO).

## Глава 2. Составные типы

### 2.1 Указатели

Указатель хранит адрес переменной в памяти. В Go, как и в C++, есть оператор `&` (взятие адреса) и оператор `*` (разыменование), но набор операций над указателями значительно уже.

```go
x := 10
p := &x   // p имеет тип *int
fmt.Println(*p) // 10
*p = 20
fmt.Println(x)  // 20
```

Ключевые отличия от указателей в C/C++:

- **Арифметика указателей запрещена.** Нельзя написать `p + 1` или `p++` — это ошибка компиляции. Такая арифметика доступна только через пакет `unsafe`, который явно выведен за пределы «безопасного» языка и почти никогда не используется в обычном коде.
- **Нет неинициализированных указателей с мусором.** Нулевое значение указателя — всегда `nil`, аналог `nullptr` в C++.
- **Разыменование `nil`-указателя вызывает панику** (`nil pointer dereference`), а не неопределённое поведение, как в C++. Программу можно перехватить через `recover`, но по умолчанию она аварийно завершится с понятной трассировкой стека.
- **Указателей на указатели, ссылок на указатели и подобных конструкций избегают** — язык не поощряет многоуровневую косвенность; вместо этого распространено возвращение указателя из функции.

Важный краевой случай, отсутствующий в C++: в Go **можно безопасно возвращать указатель на локальную переменную функции**. Компилятор проводит escape-анализ и, если видит, что переменная «убегает» за пределы функции (на неё сохраняется указатель, возвращаемый наружу), автоматически размещает такую переменную не на стеке, а в куче, продлевая её время жизни. В отличие от C++, где это было бы висячим указателем (dangling pointer) и неопределённым поведением, в Go garbage collector гарантирует, что память не будет освобождена, пока на неё есть ссылки:

```go
func newInt() *int {
    x := 10
    return &x // безопасно, компилятор перенесёт x в кучу
}
```

Для выделения памяти под новую переменную существует встроенная функция `new(T)`, возвращающая указатель `*T` на переменную с нулевым значением — эквивалент `&T{}` для структур:

```go
p := new(int)   // p — *int, *p == 0
p2 := new(Person) // эквивалентно &Person{}
```

### 2.2 Структуры

Структура (`struct`) объединяет набор именованных полей произвольных типов:

```go
type Person struct {
    Name string
    Age  int
}
```

#### Конструкторов нет

В Go отсутствует понятие конструктора как языковой конструкции. Нулевое значение структуры — это структура, все поля которой заполнены нулевыми значениями своих типов, а не «мусором»:

```go
var p Person   // Name="", Age=0
p2 := Person{} // то же самое
```

Вместо конструктора в языке принята **конвенция** — обычная функция с именем `NewXxx`, возвращающая указатель на созданную структуру:

```go
func NewPerson(name string, age int) *Person {
    return &Person{Name: name, Age: age}
}
```

Компилятор никак не отличает такую функцию от любой другой — это лишь соглашение сообщества, а не отдельная сущность языка. По той же причине в Go нет и деструкторов: используется garbage collector, а для детерминированного освобождения внешних ресурсов (файлов, соединений) применяется `defer`.

#### Копирование и передача в функции

Структура — тип-значение: при присваивании и передаче в функцию по умолчанию происходит **полное копирование** всех полей:

```go
p1 := Person{Name: "Иван"}
p2 := p1        // копия
p2.Name = "Пётр"
// p1.Name всё ещё "Иван"

func modify(p Person) { p.Name = "X" } // изменит только копию
```

Чтобы функция могла изменять оригинальный объект, структуру передают через указатель:

```go
func modifyPtr(p *Person) { p.Name = "X" } // изменит оригинал
```

#### Методы и receiver

В Go нет методов внутри объявления структуры — методы объявляются отдельно, с указанием «получателя» (receiver) перед именем функции:

```go
func (p Person) SayHello() {
    fmt.Println("Привет, меня зовут", p.Name)
}
```

Различают два вида receiver:

- **Value receiver** `(p Person)` — метод получает копию структуры; изменения полей внутри метода не затрагивают оригинал.
- **Pointer receiver** `(p *Person)` — метод получает указатель и может изменять исходный объект.

```go
func (p *Person) Birthday() {
    p.Age++ // изменяет реальный объект
}
```

Важный краевой случай: если у переменной есть value receiver методы и pointer receiver методы одновременно, Go **автоматически** берёт адрес переменной (`&p`) при вызове метода с pointer receiver, если сама переменная адресуема (то есть не является, например, временным литералом или элементом карты). Явно писать `(&p).Birthday()` не требуется.

#### Сравнение структур

Оператор `==` для структур работает «из коробки» и сравнивает все поля почленно — но только если все поля являются сравнимыми типами. Структуры, содержащие слайсы, карты или функции в качестве полей, сравнивать через `==` **нельзя** — это вызовет ошибку компиляции, поскольку сами эти типы не поддерживают сравнение на равенство (кроме сравнения с `nil`).

Перегрузка операторов (`+`, `==`, `<<` и т.д.) в Go **не поддерживается** ни для каких пользовательских типов — это осознанное решение авторов языка в пользу явности. Вместо операторов пишут обычные методы (`Add`, `Equals` и т.п.). Для кастомизации текстового представления структуры (аналог `operator<<` в C++) используется интерфейс `Stringer`:

```go
func (p Person) String() string {
    return fmt.Sprintf("%s (%d лет)", p.Name, p.Age)
}
```

#### Встраивание (embedding) вместо наследования

Go не поддерживает наследование классов. Вместо него используется встраивание одной структуры в другую:

```go
type Animal struct {
    Name string
}

func (a Animal) Eat() {
    fmt.Println(a.Name, "ест")
}

type Dog struct {
    Animal // встраивание, а не наследование
    Breed string
}
```

При встраивании поля и методы вложенной структуры «поднимаются» наверх, и к ним можно обращаться напрямую: `d.Name` вместо `d.Animal.Name`, `d.Eat()` вместо `d.Animal.Eat()`.

Принципиальный краевой случай, отличающий Go от C++: встраивание **не создаёт отношения подтипа**. `Dog` не является `Animal` с точки зрения системы типов, поэтому значение `*Dog` **нельзя** передать в функцию, ожидающую `*Animal` — это ошибка компиляции, в отличие от C++, где `Dog*` неявно приводится к `Animal*` при публичном наследовании:

```go
func TakeAnimal(a *Animal) { a.Eat() }

d := Dog{Animal: Animal{Name: "Рекс"}}
TakeAnimal(&d) // ОШИБКА КОМПИЛЯЦИИ: *Dog не является *Animal
TakeAnimal(&d.Animal) // ОК — явное обращение к встроенному полю
```

Полиморфизм в Go достигается не через встраивание, а через интерфейсы (см. далее).

### 2.3 Интерфейсы

Интерфейс описывает набор методов (контракт) без какой-либо реализации и без полей:

```go
type Speaker interface {
    Speak() string
}
```

#### Структурная типизация (duck typing)

В отличие от Java/C++, в Go **не нужно** явно объявлять, что тип реализует интерфейс. Достаточно, чтобы у типа были все методы с точно такими же сигнатурами, как в интерфейсе, — тогда компилятор автоматически считает такой тип соответствующим интерфейсу:

```go
type Dog struct{ Name string }
func (d Dog) Speak() string { return "Гав" }

var s Speaker = Dog{Name: "Рекс"} // ОК: Dog неявно реализует Speaker
```

Важный краевой случай: реализация интерфейса требует покрытия **всех** методов интерфейса, а не части. Если интерфейс объявляет два метода, а тип реализует только один, попытка присвоить значение такого типа переменной интерфейсного типа — ошибка компиляции:

```go
type Speaker interface {
    Speak() string
    Listen() string
}

type Dog struct{}
func (d Dog) Speak() string { return "Гав" }
// Listen() не реализован

var s Speaker = Dog{} // ОШИБКА: Dog does not implement Speaker (missing method Listen)
```

Внутреннее устройство интерфейсного значения можно представить как пару (тип, значение): интерфейсная переменная хранит и конкретный динамический тип, и само значение этого типа.

#### Полиморфизм через интерфейсы

Функции, принимающие интерфейс, могут работать с любой реализующей его структурой, не зная заранее о её конкретном типе:

```go
func MakeItSpeak(s Speaker) {
    fmt.Println(s.Speak())
}
```

Аналогично можно хранить разнородные значения в одной коллекции, объединённые общим интерфейсом:

```go
animals := []Speaker{Dog{Name: "Рекс"}, Cat{Name: "Мурка"}}
for _, a := range animals {
    fmt.Println(a.Speak())
}
```

#### Приведение к конкретному типу

Type assertion позволяет извлечь конкретное значение из интерфейсной переменной:

```go
if dog, ok := s.(Dog); ok {
    fmt.Println("Это собака:", dog.Name)
}
```

Если использовать однозначную форму без `ok` (`dog := s.(Dog)`) и фактический тип не совпадёт — произойдёт паника, а не тихая некорректная интерпретация памяти, как при неудачном `reinterpret_cast` в C++.

Для проверки сразу нескольких возможных типов применяется `type switch`:

```go
switch v := s.(type) {
case Dog:
    fmt.Println("Собака:", v.Name)
case Cat:
    fmt.Println("Кошка:", v.Name)
default:
    fmt.Println("Неизвестное животное")
}
```

#### Пустой интерфейс

`interface{}` (начиная с Go 1.18 обычно записывается как псевдоним `any`) не требует от типа никаких методов, поэтому в переменную такого типа можно поместить значение любого типа:

```go
func PrintAnything(v any) {
    fmt.Println(v)
}
```

В отличие от `void*` в C, значение остаётся типобезопасным: динамический тип сохраняется внутри интерфейсного значения, и его можно проверить через type assertion или type switch.

### 2.4 Массивы и слайсы

#### Массивы

Массив — это последовательность элементов **фиксированной длины**, которая является частью типа:

```go
var a [5]int // массив из 5 int, все элементы == 0
b := [3]string{"a", "b", "c"}
```

Важный краевой случай: `[5]int` и `[3]int` — это **разные, несовместимые типы**. Массив, в отличие от слайса, при присваивании и передаче в функцию копируется целиком, как обычная структура:

```go
func modify(arr [5]int) {
    arr[0] = 100 // изменит только копию
}
```

На практике массивы используются редко — почти везде вместо них применяются слайсы.

#### Слайсы

Слайс (`slice`) — динамическая, изменяемая по длине структура, представляющая собой «окно» в базовый массив. Внутри слайс хранит указатель на начало данных, длину (`len`) и ёмкость (`cap`).

```go
s := []int{1, 2, 3}       // литерал слайса
s2 := make([]int, 5)      // слайс длины 5, заполнен нулями
s3 := make([]int, 5, 10)  // длина 5, ёмкость 10
```

**Нулевое значение слайса — `nil`**, и это не то же самое, что пустой слайс (хотя оба имеют длину 0):

```go
var s []int           // nil, len == 0
s2 := []int{}          // не nil, len == 0
fmt.Println(s == nil)  // true
fmt.Println(s2 == nil) // false
```

Несмотря на то что `s` равен `nil`, к нему можно безопасно применять `append` — Go самостоятельно выделит новый массив:

```go
var s []int
s = append(s, 1) // ОК, паники не произойдёт
```

А вот обращение по индексу к `nil`-слайсу или слайсу нулевой длины приведёт к панике `index out of range`, поскольку под индексом физически нет элемента:

```go
var s []int
s[0] = 1 // ПАНИКА: index out of range [0] with length 0
```

**Слайсы разделяют общий базовый массив.** Это важнейший краевой случай, отличающий Go-слайсы от, например, `std::vector`: два слайса, полученные один из другого через операцию среза (`s[a:b]`), могут указывать на один и тот же участок памяти, и изменение элемента через один слайс отразится на другом:

```go
a := []int{1, 2, 3, 4, 5}
b := a[1:3]  // {2, 3}, но использует ту же память, что и a
b[0] = 100
fmt.Println(a) // [1 100 3 4 5] — изменился и a!
```

При этом `append` может как продолжить писать в тот же базовый массив (если хватает ёмкости `cap`), так и **выделить новый массив** (если ёмкости не хватает) — во втором случае связь между старым и новым слайсом теряется:

```go
a := make([]int, 3, 3) // len=3, cap=3, ёмкость исчерпана
b := append(a, 4)      // выделится новый массив, b больше не связан с a
```

Это одна из самых частых практических ошибок в Go: код полагается на то, что `append` либо всегда изменяет исходный слайс, либо никогда — тогда как поведение зависит от текущей ёмкости.

### 2.5 Map

`map[K]V` — ассоциативный массив (хеш-таблица), сопоставляющий ключи типа `K` значениям типа `V`. В качестве ключа допускается любой сравнимый тип (числа, строки, структуры без слайсов/карт/функций внутри); слайсы, карты и функции ключами быть не могут.

```go
m := map[string]int{"a": 1, "b": 2}
m2 := make(map[string]int) // пустая, но инициализированная карта
```

**Нулевое значение карты — `nil`.** Важный краевой случай: из `nil`-карты **можно читать** (вернётся нулевое значение типа `V`, как если бы ключ существовал и был равен нулю), но **запись в неё вызывает панику**:

```go
var m map[string]int
fmt.Println(m["a"]) // 0 — чтение безопасно, паники нет
m["a"] = 1           // ПАНИКА: assignment to entry in nil map
```

Поэтому перед первой записью карту обязательно нужно инициализировать через `make` или через литерал.

**Проверка существования ключа.** Обращение `m[key]` не позволяет отличить «ключ отсутствует» от «ключ присутствует и его значение равно нулю» — для этого используется двузначная форма:

```go
value, ok := m["x"]
if !ok {
    fmt.Println("ключ отсутствует")
}
```

**Порядок итерации не гарантирован.** При переборе карты через `for range` порядок ключей не определён языком и может отличаться от запуска к запуску — специально рандомизируется рантаймом, чтобы код не мог случайно на него положиться.

**Удаление ключа** выполняется встроенной функцией `delete(m, key)`; попытка удалить несуществующий ключ не приводит к ошибке — это допустимая операция, ничего не делающая.

**Конкурентный доступ.** Обычная карта в Go **не является потокобезопасной**: одновременное чтение и запись из разных горутин без синхронизации приведёт к панике времени выполнения (`concurrent map read and map write`), которую рантайм обнаруживает и явно сообщает, а не оставляет как молчаливое неопределённое поведение. Для конкурентного доступа используют мьютексы (`sync.Mutex`) или специализированный тип `sync.Map`.
