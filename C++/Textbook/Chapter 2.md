# II. Составные типы в C++

## §2.1. Указатели

Каждый объект занимает некоторое место в памяти. У этого места есть адрес, по которому программа может обратиться к объекту.

Оператор `&` возвращает адрес объекта, а оператор `*` позволяет обратиться к объекту по адресу:

```cpp
int x = 5;
int* p = &x;

*p = 7;
```

Здесь:

- `x` — объект типа `int`;
- `&x` — адрес объекта `x`;
- `p` — указатель, в котором хранится этот адрес;
- `*p` — тот объект, на который указывает `p`, то есть `x`.

После выполнения `*p = 7` значение `x` также станет равно `7`. Новый объект типа `int` не создаётся: выражения `x` и `*p` позволяют обратиться к одному и тому же объекту двумя разными способами.

Выражение `*p` является lvalue: оно обозначает существующий объект, поэтому слева от присваивания можно написать `*p`. Результат `&x` — новое значение-адрес типа `int*`, то есть prvalue. Здесь эти термины описывают категории выражений, а не отдельные разновидности памяти.

### Тип указателя

Если объект имеет тип `T`, указатель на него имеет тип `T*`:

```cpp
double value = 1.5;
double* pointer = &value;
```

Тип указателя сообщает компилятору, объект какого типа находится по сохранённому адресу. Это необходимо, в частности, чтобы правильно выполнить разыменование и арифметику указателей.

Символ `*` используется в двух разных смыслах:

```cpp
int* p = &x; // * участвует в записи типа int*
int y = *p;  // * — оператор разыменования
```

В объявлении нескольких переменных `*` относится к конкретному имени, поэтому его нужно указывать для каждого указателя:

```cpp
int* p, *q; // p и q — указатели
int* r, x;  // r — указатель, x — обычный int
```

Из-за этого объявления указателей нередко записывают по одному на строку.

Размер указателя обычно зависит от платформы и режима компиляции, а не от размера объекта, на который он указывает. Например, в типичной 64-битной программе указатели на `char`, `int` и `double` занимают по 8 байт. Стандарт C++ не требует ни размера в 8 байт, ни одинакового представления всех возможных видов указателей, поэтому полагаться на это как на правило языка нельзя.

При выводе указателя потоки обычно показывают адрес в шестнадцатеричном виде:

```cpp
std::cout << p << '\n';
```

Конкретное значение адреса заранее неизвестно и может меняться между запусками программы.

### Арифметика указателей

Указатель можно сдвигать не на произвольное количество байт, а на элементы его типа:

```cpp
int values[] = {10, 20, 30, 40};
int* p = values;

++p;
std::cout << *p << '\n';
```

> Вывод: `20`.

После `++p` указатель указывает на следующий `int`. Если `sizeof(int) == 4`, его числовой адрес обычно увеличится на 4 байта, однако код описывает переход именно к следующему элементу, а не прибавление четырёх байт.

Для указателя `p` и целого `n` доступны выражения `p + n`, `p - n`, `p += n`, `p -= n`, `++p` и `--p`. Но такая арифметика определена только в пределах одного массива. Допускается также получить адрес сразу после последнего элемента:

```cpp
int values[4]{};

int* begin = values;
int* end = values + 4; // допустимый указатель за концом массива
```

`end` удобно использовать как границу диапазона, но разыменовывать его нельзя: за ним нет элемента массива.

```cpp
// int x = *end; // UB: попытка обратиться к несуществующему элементу
```

Даже если случайное числовое значение адреса выглядит правдоподобно, это не делает произвольную арифметику указателей допустимой. Компилятор рассуждает не только о числах, но и о том, к какому массиву относится указатель.

Два указателя на элементы одного массива можно вычесть:

```cpp
int values[10]{};
int* first = &values[2];
int* last = &values[7];

std::ptrdiff_t distance = last - first;
```

`distance` будет равен `5`: результат выражается в элементах, а не в байтах. Тип результата — `std::ptrdiff_t`, определённый в `<cstddef>`. Вычитание указателей, не относящихся к одному массиву, недопустимо.

Указатели можно сравнивать на равенство. Упорядочивающие сравнения (`<`, `>`, `<=`, `>=`) надёжно описывают порядок элементов одного массива. Для произвольных несвязанных объектов по таким сравнениям не следует пытаться определять их «порядок в памяти».

### Указатель на указатель

Сам указатель тоже является объектом, поэтому у него есть собственный адрес:

```cpp
int x = 5;
int* p = &x;
int** pp = &p;

**pp = 8;
```

`pp` имеет тип `int**` — указатель на указатель на `int`. Выражение `*pp` обозначает `p`, а `**pp` обозначает `x`. После присваивания значение `x` станет равно `8`.

Операторы `&` и `*` действительно могут компенсировать друг друга:

```cpp
*&p == p;
&*p == p;
*&*&*&p == p;
```

Однако второе выражение имеет смысл только для указателя, который можно корректно разыменовать. Это правило нельзя использовать, чтобы сделать допустимым `*nullptr` или обращение через висячий указатель.

### Нулевые, неинициализированные и висячие указатели

`nullptr` — литерал нулевого указателя. Он обозначает, что указатель сейчас не указывает ни на какой объект:

```cpp
int* p = nullptr;
```

Тип самого литерала `nullptr` — `std::nullptr_t`, но он неявно преобразуется в указатель любого подходящего типа. Разыменование нулевого указателя приводит к UB:

```cpp
// std::cout << *p; // UB
```

Указатель без инициализации содержит неопределённое значение. Его нельзя читать и тем более разыменовывать:

```cpp
int* p; // не указывает на заранее известный объект
// *p = 10; // UB
```

Если объект уже уничтожен, сохранённый адрес становится висячим указателем:

```cpp
int* p = nullptr;

{
    int x = 42;
    p = &x;
} // время жизни x закончилось

// std::cout << *p; // UB: объекта x больше нет
```

Важно различать сам указатель и обращение через него. Хранение нулевого указателя или указателя за концом массива допустимо. Ошибка возникает, когда программа пытается использовать такой указатель так, будто по нему находится живой объект.

### `void*`

`void*` — указатель, в типе которого не записано, на объект какого типа он указывает:

```cpp
int x = 5;
void* raw = &x;
```

Напрямую разыменовать `void*` нельзя. Это не UB, а ошибка компиляции: компилятор не знает ни тип объекта, ни тип результата `*raw`.

```cpp
// int y = *raw; // ошибка компиляции: void* нельзя разыменовать
```

Сначала нужно восстановить правильный тип указателя:

```cpp
int* p = static_cast<int*>(raw);
std::cout << *p << '\n';
```

> Вывод: `5`.

Приведение не проверяет, действительно ли по адресу находится `int`. Если восстановить неверный тип, последующее обращение к объекту может привести к UB.

### Передача адреса в функцию

При обычной передаче по значению функция получает копии аргументов:

```cpp
void swap(int x, int y) {
    int temporary = x;
    x = y;
    y = temporary;
}

int a = 1;
int b = 2;
swap(a, b);
```

После вызова `a` и `b` не изменятся. Имена `x` и `y` обозначают отдельные локальные объекты, а не исходные переменные.

Если передать адреса, функция сможет обратиться к исходным объектам:

```cpp
void swap(int* x, int* y) {
    int temporary = *x;
    *x = *y;
    *y = temporary;
}

int a = 1;
int b = 2;
swap(&a, &b);
```

После вызова `a == 2`, а `b == 1`. Функция разыменовывает полученные адреса и изменяет сами объекты `a` и `b`. Такая реализация требует, чтобы оба аргумента указывали на действительные объекты; при возможности передать `nullptr` это нужно отдельно обработать.

## §2.2. Виды памяти и время жизни объектов

Операционная система предоставляет запущенной программе память, но стандарт C++ описывает прежде всего объекты, их время жизни и длительность хранения. Привычные слова «стек» и «куча» полезны для понимания обычной реализации, однако это не основные термины правил языка.

Упрощённо в процессе можно увидеть области с машинным кодом, статическими данными, стеком вызовов и динамически выделяемой памятью. Конкретное устройство исполняемого файла и адресного пространства зависит от операционной системы, компилятора и платформы.

В C++ различают несколько видов длительности хранения:

- **автоматическая** — локальный объект обычно создаётся при входе в блок и уничтожается при выходе из него;
- **статическая** — объект существует в течение всей программы;
- **потоковая** (`thread_local`) — отдельный объект существует для каждого потока;
- **динамическая** — время жизни объекта управляется операциями динамического выделения памяти.

### Автоматические объекты

```cpp
void f() {
    int x = 5;
} // x уничтожается здесь
```

`x` имеет автоматическую длительность хранения. В обычной реализации он будет связан со стеком вызова `f`, но стандарт не обязывает компилятор физически помещать его именно туда: значение может находиться, например, в регистре или вообще исчезнуть после оптимизации.

### Статические объекты

Глобальные переменные и переменные, объявленные с `static`, имеют статическую длительность хранения:

```cpp
void count_calls() {
    static int calls = 0;
    ++calls;
    std::cout << calls << '\n';
}

count_calls();
count_calls();
```

> Вывод:
>
> ```text
> 1
> 2
> ```

Локальная переменная `calls` видна только внутри функции, но создаётся один раз и сохраняет значение между вызовами. Выполнение снова доходит до её объявления, однако повторной инициализации не происходит. Начиная с C++11 инициализация локальной статической переменной защищена от одновременного выполнения несколькими потоками.

Строковые литералы также существуют всю программу, но попытка изменить их содержимое недопустима.

### Динамические объекты

Оператор `new` выделяет подходящую память, создаёт в ней объект и возвращает указатель:

```cpp
int* p = new int{42};

std::cout << *p << '\n';

delete p;
p = nullptr;
```

> Вывод: `42`.

`delete` завершает время жизни объекта и освобождает память, полученную обычным `new`. После `delete p` старый адрес больше нельзя разыменовывать. Присваивание `nullptr` не освобождает память само по себе, но помогает не использовать случайно уже освобождённый адрес.

Способ инициализации имеет значение:

```cpp
int* a = new int;    // значение int не инициализировано
int* b = new int{};  // значение равно 0

delete a;
delete b;
```

Чтение `*a` до присваивания было бы недопустимым. Фигурные скобки в `new int{}` выполняют инициализацию значением, поэтому `*b == 0`.

Каждому успешно созданному динамическому объекту должен соответствовать ровно один корректный способ освобождения:

- результат `new T` освобождается через `delete`;
- результат `new T[n]` освобождается через `delete[]`;
- память от `malloc` освобождается через `free`.

Смешивать эти пары нельзя. Повторный `delete` одного объекта и обращение к нему после освобождения приводят к UB. `delete nullptr`, напротив, безопасен и ничего не делает.

Если программа потеряет все указатели на выделенный объект, освободить его обычным способом уже не получится:

```cpp
int* p = new int{42};
p = nullptr; // адрес потерян, произошла утечка памяти
```

Сама по себе граница области видимости не обязательно создаёт утечку. Указатель можно вернуть из функции или сохранить в другом объекте. Утечка появляется тогда, когда память всё ещё занята, но программа больше не хранит способ добраться до неё и освободить её.

В C++ есть унаследованные от C функции `malloc` и `free`. `malloc` выделяет сырой блок байтов, но не выполняет обычное создание и инициализацию объекта так, как это делает `new`. В современном C++ ручное управление памятью стараются заменять контейнерами и объектами-владельцами: `std::vector`, `std::string`, `std::unique_ptr` и другими средствами RAII.

## §2.3. Массивы

Встроенный массив — это последовательность объектов одного типа, расположенных подряд:

```cpp
int a[5];                  // пять неинициализированных int
int b[] = {1, 2, 3, 4, 5}; // размер 5 выведен из инициализатора
int c[5] = {1, 2};         // {1, 2, 0, 0, 0}
int d[5]{};                // {0, 0, 0, 0, 0}
```

В первом случае локальные элементы фундаментального типа не получают определённых значений. Читать их до присваивания нельзя. В третьем случае явно заданы только первые два элемента, а все оставшиеся инициализируются нулями.

Встроенный массив не обязан находиться на стеке. Он может иметь автоматическую, статическую или динамическую длительность хранения — это зависит от того, где и как он создан.

Размер обычного массива в объявлении должен быть константным выражением:

```cpp
constexpr std::size_t size = 10;
int values[size];
```

```cpp
std::size_t size;
std::cin >> size;
// int values[size]; // не стандартный C++
```

Некоторые компиляторы разрешают массивы переменной длины как расширение языка, но переносимый C++-код не должен на них рассчитывать. Если размер становится известен только во время выполнения, обычно используют `std::vector<T>`.

### Индексация и преобразование к указателю

Индексы массива из `N` элементов находятся в диапазоне от `0` до `N - 1`:

```cpp
int values[] = {10, 20, 30, 40};

std::cout << values[0] << '\n'; // 10
std::cout << values[3] << '\n'; // 40
```

Обращения `values[-1]` и `values[4]` выходят за границы массива и приводят к UB. Встроенный массив сам не проверяет индекс во время выполнения.

В большинстве выражений имя массива неявно преобразуется в указатель на его первый элемент:

```cpp
int* p = values;

int x = *(values + 2);
int y = values[2];
int z = 2[values];
```

Все три переменные получат значение `30`, потому что операция `a[b]` определяется через `*(a + b)`. Запись `2[values]` допустима по тем же правилам, но ухудшает читаемость и в обычном коде не используется.

От указателя на элемент можно двигаться назад, пока результат остаётся в пределах того же массива:

```cpp
int* p = values + 3;
std::cout << p[-1] << '\n';
```

> Вывод: `30`.

### Массив не является указателем

Преобразование имени массива к указателю происходит часто, но сам массив и указатель — разные типы:

```cpp
int values[5]{};
int* p = values;

sizeof(values); // размер всех пяти элементов
sizeof(p);      // размер одного указателя
```

Если `sizeof(int) == 4`, первое выражение даст `20`. Второе на типичной 64-битной платформе даст `8`, но оба конкретных числа зависят от платформы.

Преобразования к указателю нет, когда массив используется как операнд `sizeof` или когда у него берут адрес оператором `&`:

```cpp
int (*pointer_to_array)[5] = &values;
```

`values` при обычном преобразовании имеет тип `int*`, а `&values` имеет тип `int (*)[5]` — указатель на весь массив из пяти `int`. Числовой адрес начала может выглядеть одинаково, но прибавление единицы к этим указателям означало бы разный сдвиг.

Встроенные массивы нельзя присваивать друг другу и нельзя увеличивать:

```cpp
int a[3]{};
int b[3]{};

// a = b; // ошибка компиляции
// ++a;   // ошибка компиляции
```

Для объекта `std::array<T, N>` присваивание поддерживается, поэтому при необходимости обычной семантики значения он часто удобнее встроенного массива.

### Передача массива в функцию

В списке параметров запись массива автоматически корректируется до указателя:

```cpp
void f(int values[]);
void f(int* values);
```

Для компилятора это объявления одной и той же функции. Внутри `f` параметр `values` является указателем, поэтому `sizeof(values)` возвращает размер указателя, а не исходного массива. Размер нужно передать отдельно:

```cpp
void print(const int* values, std::size_t size) {
    for (std::size_t i = 0; i < size; ++i) {
        std::cout << values[i] << ' ';
    }
}
```

Другие способы сохранить информацию о размере — принять массив по ссылке, использовать шаблон или передать `std::span` начиная с C++20.

### Динамический массив

Размер массива, создаваемого через `new[]`, может быть известен только во время выполнения:

```cpp
std::size_t size;
std::cin >> size;

int* values = new int[size]{};

// Работа с values[0] ... values[size - 1].

delete[] values;
```

`values` — указатель, поэтому из него нельзя автоматически узнать число элементов. Реализация может хранить служебные данные, необходимые для `delete[]`, рядом с выделенной памятью, но их наличие и расположение стандартом не обещано. Программа не должна пытаться читать эти данные самостоятельно.

Для динамической последовательности почти всегда безопаснее `std::vector<int>`: он хранит размер и освобождает память автоматически.

### Многомерные массивы

```cpp
int matrix[3][5];
```

`matrix` — массив из трёх элементов, каждый из которых является массивом из пяти `int`. Все 15 чисел расположены последовательно, строка за строкой.

Скобки существенно меняют смысл объявления:

```cpp
int* pointers[5]; // массив из пяти указателей на int
int (*row)[5];    // указатель на массив из пяти int
```

Объявление удобно читать от имени переменной с учётом скобок. У `pointers` сначала видим `[5]`, поэтому это массив; его элементы имеют тип `int*`. У `row` скобки заставляют сначала прочитать `*row`, поэтому это указатель; он указывает на объект типа `int[5]`.

При передаче двумерного массива в функцию его тип корректируется до указателя на строку:

```cpp
void process(int matrix[][5]);
// То же самое:
void process(int (*matrix)[5]);
```

Это не `int**`. Указатель `int**` ведёт к объекту-указателю, а `int (*)[5]` — к непрерывному массиву из пяти `int`. Разные способы размещения данных требуют разных вычислений адреса, поэтому компилятор не может считать эти типы взаимозаменяемыми.

## §2.4. Функции и указатели на функции

Функция связывает имя с последовательностью действий. Объявление сообщает компилятору тип функции, а определение содержит её тело:

```cpp
int sum(int, int); // объявление; имена параметров можно не писать

int sum(int a, int b) { // определение
    return a + b;
}
```

Совместимое объявление функции можно встретить несколько раз. Определение в программе в общем случае должно быть одно и обязано соблюдать ODR. То есть верно не «функцию можно определять сколько угодно раз», а «функцию можно несколько раз объявить».

При передаче по значению параметры являются отдельными объектами:

```cpp
void increment(int value) {
    ++value;
}

int x = 0;
increment(x);
```

`x` останется равен `0`, потому что функция изменила локальный параметр `value`. Для классов создание параметра может означать копирование или перемещение, хотя компилятор в некоторых ситуациях имеет право устранить лишнее создание объекта.

`return` завершает текущий вызов. В функции с возвращаемым типом, отличным от `void`, результат выражения преобразуется к объявленному типу функции, если такое преобразование допустимо.

### Аргументы по умолчанию

```cpp
void print_number(int value, int base = 10);

print_number(42);    // компилятор подставит 10
print_number(42, 2); // явно передано 2
```

Аргумент по умолчанию подставляется в месте вызова. Обычно после первого параметра со значением по умолчанию все следующие параметры тоже должны уже иметь доступные значения по умолчанию:

```cpp
void f(int x, int y = 1, int z = 2); // корректно
// void g(int x = 1, int y);          // некорректно
```

Значение не обязано быть записано непосредственно в определении функции: его часто указывают в объявлении в заголовочном файле, чтобы оно было видно вызывающему коду. Повторять одно и то же значение по умолчанию в нескольких объявлениях одной области нельзя.

### C-подобные вариативные функции

Запись `...` позволяет принять неизвестное заранее число аргументов:

```cpp
void log_values(const char* format, ...);
```

Такая функция извлекает аргументы через средства `<cstdarg>`. Типы дополнительных аргументов не описаны сигнатурой, поэтому компилятор располагает меньшим количеством возможностей проверить вызов. Функции нужен отдельный способ понять количество и типы значений — например, форматная строка. Ошибка в этом соглашении может привести к UB. В современном C++ чаще используют вариативные шаблоны и типобезопасные библиотеки форматирования.

### Указатели на функции

У функции тоже можно взять адрес:

```cpp
bool less(int x, int y) {
    return x < y;
}

bool (*compare)(int, int) = &less;
bool result = compare(1, 2);
```

`compare` — указатель на функцию, которая принимает два `int` и возвращает `bool`. Результат вызова будет равен `true`.

Оператор `&` можно опустить: имя функции в подходящем контексте само преобразуется в указатель.

```cpp
bool (*compare)(int, int) = less;
```

Если функция перегружена, ожидаемый тип иногда позволяет выбрать нужную перегрузку:

```cpp
void print(int);
void print(double);

void (*p)(int) = &print; // выбрана print(int)
```

Без контекста компилятор не может понять, адрес какой перегрузки требуется:

```cpp
// auto p = &print; // ошибка компиляции: имя обозначает несколько функций
```

Тип указателя должен описывать совместимую сигнатуру. Указатель на функцию не следует считать обычным указателем на объект: например, стандартный переносимый C++ не обещает преобразование указателя на функцию в `void*` и обратно.

Сложные объявления читаются от имени наружу:

```cpp
void (*(*p[10])(int))(int);
```

`p` — массив из десяти указателей на функции. Каждая такая функция принимает `int` и возвращает указатель на другую функцию, которая тоже принимает `int`, но возвращает `void`.

Подобный тип намного понятнее выразить через псевдонимы:

```cpp
using InnerFunction = void (*)(int);
using OuterFunction = InnerFunction (*)(int);

OuterFunction p[10];
```

Обе записи задают один смысл, но вторая позволяет назвать уровни типа и уменьшает вероятность ошибки.

## §2.5. Ссылки

Ссылка — ещё одно имя уже существующего объекта:

```cpp
int x = 4;
int& reference = x;

reference = 9;
```

После присваивания `x == 9`. Отдельный объект типа `int` не создаётся: `x` и `reference` обозначают один объект.

Обычную lvalue-ссылку необходимо сразу связать с подходящим объектом:

```cpp
int x = 0;
int& reference = x;
```

Ссылку нельзя позже «перенаправить»:

```cpp
int x = 1;
int y = 2;
int& reference = x;

reference = y;
```

Последняя строка присваивает значение `y` объекту `x`; она не заставляет `reference` обозначать `y`.

Нельзя создать обычную ссылку без инициализатора, ссылку на `void` или массив ссылок. При этом можно создать ссылку на массив, указатель или функцию:

```cpp
int values[3]{};
int (&array_reference)[3] = values;

int* pointer = values;
int*& pointer_reference = pointer;
```

В исходном тексте фраза «нельзя создать ссылку на другую ссылку» требует уточнения. После применения правил языка итоговый тип ссылки на ссылку не возникает, но записи с несколькими `&` встречаются в псевдонимах и шаблонах. Там работают правила свёртки ссылок.

Ссылка сама по себе не управляет временем жизни объекта. Она может стать висячей, если объект уничтожен. Представлять ссылку как автоматически разыменовываемый указатель иногда удобно, однако стандарт не требует именно такого физического представления.

### Передача по ссылке

```cpp
void increment(int& value) {
    ++value;
}

int x = 0;
increment(x);
```

После вызова `x == 1`, потому что параметр `value` является ссылкой на исходный объект.

Можно объявить перегрузки, принимающие `int` и `int&`, но вызов с обычной переменной окажется неоднозначным:

```cpp
void f(int);
void f(int&);

int x = 0;
// f(x); // ошибка компиляции: подходят обе перегрузки
```

Компилятор не считает вариант со ссылкой безусловно «лучше» варианта со значением.

Обмен через ссылки записывается проще, чем через указатели:

```cpp
void swap(int& x, int& y) {
    int temporary = x;
    x = y;
    y = temporary;
}
```

В исходном варианте последней строкой было `y = x`. Это потеряло бы старое значение `x`: после `x = y` обе переменные получили бы первоначальное значение `y`. Старое значение было сохранено в `temporary`, поэтому именно его нужно присвоить `y`.

### Возврат ссылки

Функция может вернуть ссылку на объект, который продолжает существовать после её завершения:

```cpp
int& increment(int& x) {
    return ++x;
}

int x = 0;
increment(x) = 10;
```

`++x` возвращает lvalue, обозначающее изменённый `x`, поэтому функция возвращает ссылку на исходный объект. Результату вызова можно присвоить значение, и после последней строки `x == 10`.

Если результат используется для инициализации обычной переменной, значение копируется:

```cpp
int y = increment(x);
```

`y` — новый объект, а не ссылка. Чтобы сохранить ссылку, нужно явно написать `int& y = increment(x);`.

Нельзя возвращать ссылку на локальную автоматическую переменную:

```cpp
int& wrong(int x) {
    int local = x + 1;
    return local;
}
```

`local` уничтожается при выходе из функции, поэтому возвращённая ссылка сразу становится висячей. Компилятор обычно предупреждает об этом, но программа может собраться. Ошибка проявляется при использовании ссылки, и такое обращение приводит к UB. Это не обязано быть ошибкой компиляции.

## §2.6. Константность

`const` запрещает изменять объект через данное имя или данный путь доступа:

```cpp
const int value = 5;

int result = value + 1; // допустимо: value только читается
// value = 7;           // ошибка компиляции: попытка изменить value
// ++value;             // ошибка компиляции: попытка изменить value
```

Константный объект можно читать, сравнивать и использовать в вычислениях. Запрещены именно операции, которые пытаются его изменить. Поэтому утверждение, что для `const int` запрещено сложение или вычитание, неверно.

Обычный локальный `const`-объект нужно инициализировать, потому что присвоить ему значение позже уже нельзя.

### Указатель на константный объект

```cpp
int x = 0;
int y = 1;

const int* p = &x;
// *p = 5; // ошибка компиляции: через p объект менять нельзя
p = &y;    // сам указатель менять можно
```

Записи `const int*` и `int const*` означают одно и то же: изменяемый указатель на `const int`. Константность находится на уровне объекта, доступного после разыменования.

Если исходный объект не был объявлен константным, его всё ещё можно изменить другим путём:

```cpp
int x = 0;
const int* p = &x;

x = 5; // допустимо
```

`p` обещает только то, что программа не будет менять `x` через `*p`. Он не превращает сам объект `x` в константный.

Обратное преобразование запрещено:

```cpp
const int value = 1;
const int* source = &value;
// int* destination = source; // ошибка компиляции
```

Если бы оно было разрешено, через `destination` можно было бы попытаться изменить настоящий константный объект.

### Константный указатель

```cpp
int x = 0;
int y = 1;

int* const p = &x;

*p = 5;   // допустимо: x изменяемый
// p = &y; // ошибка компиляции: адрес в p менять нельзя
```

`int* const` — константный указатель на изменяемый `int`. Сам `p` нельзя переназначить, но объект по адресу изменять можно.

Оба уровня могут быть константными:

```cpp
const int* const p = &x;
```

Через `p` нельзя изменить число, и сам `p` нельзя переназначить.

### Почему `T**` нельзя преобразовать в `const T**`

Преобразование `T*` в `const T*` безопасно, но применять его сразу через дополнительный уровень указателя нельзя:

```cpp
const char constant = 'a';
char* pointer = nullptr;

// const char** outer = &pointer; // ошибка компиляции
```

Представим, что компилятор разрешил последнюю строку:

```cpp
// *outer = &constant;
// *pointer = 'b';
```

Через `outer` в обычный `char*` удалось бы записать адрес константного `char`. После этого тип `pointer` по-прежнему обещал бы доступ к изменяемому `char`, и последняя строка попыталась бы изменить константный объект. Чтобы не создавать такой путь обхода `const`, компилятор запрещает исходное преобразование.

### Константные ссылки

```cpp
int x = 0;
const int& reference = x;

// reference = 1; // ошибка компиляции
x = 1;            // допустимо
```

Как и указатель на `const`, ссылка запрещает изменение через себя, но не делает исходный изменяемый объект константным.

Запись `int& const` запрещена. Обычная ссылка и так не может быть перенаправлена, поэтому отдельная верхнеуровневая константность для неё не имеет смысла.

`const T&` может связываться с временным объектом:

```cpp
const std::string& text = std::string("abc");
```

При таком прямом связывании время жизни временной строки продлевается до времени жизни `text`.

Это правило имеет важные границы. Временный объект, связанный с параметром функции, существует только до конца полного выражения с вызовом:

```cpp
void print(const std::string& text) {
    std::cout << text << '\n';
}

print("abc");
```

Строковый литерал преобразуется во временный `std::string`, который гарантированно существует во время `print`. После завершения всего выражения `print("abc");` временная строка уничтожается. Функция не должна сохранять ссылку на неё для последующего использования.

Обычная неконстантная lvalue-ссылка `T&` с временным значением не связывается:

```cpp
void increment(std::size_t& value) {
    ++value;
}

int x = 0;
// increment(x); // ошибка компиляции
```

Для вызова понадобилось бы создать временный `std::size_t` из `x`. Изменение такого временного объекта не изменило бы `x`, поэтому язык не разрешает скрыть эту ситуацию за параметром `std::size_t&`.

`const` — свойство типа и пути доступа, а не гарантия того, что соответствующие байты физически никогда не изменятся. Например, исходный объект мог быть неконстантным и измениться через другое имя. Позже в ООП также появятся `const`-методы и поля `mutable`.

## §2.7. Приведения типов

Приведение типа явно просит интерпретировать или преобразовать выражение по правилам другого типа. Явная запись не делает опасную операцию безопасной: она лишь показывает намерение программиста и выбирает определённый набор правил.

В C++ используются `static_cast`, `reinterpret_cast`, `const_cast`, `dynamic_cast` и приведение в стиле C.

### `static_cast`

`static_cast` выполняет преобразования, связь между которыми известна языку и проверяется при компиляции:

```cpp
int x = 3;
double value = static_cast<double>(x);
```

`value` станет равен `3.0`. Здесь создаётся значение типа `double`; биты объекта `x` не переосмысливаются как `double`.

`static_cast` может выполнять и сужающее преобразование:

```cpp
double value = 3.9;
int x = static_cast<int>(value); // x == 3
```

Дробная часть отбрасывается. Явность показывает, что программист запросил преобразование, но не гарантирует отсутствие потери информации. Для значений вне представимого диапазона действуют отдельные правила, которые тоже нужно учитывать.

Указатель на объект можно преобразовать в `void*` и затем восстановить исходный тип:

```cpp
int x = 5;
void* raw = static_cast<void*>(&x);
int* restored = static_cast<int*>(raw);
```

После восстановления правильного типа `*restored` обозначает `x`. Если привести `raw` к неподходящему типу и обратиться через него к объекту, одна лишь запись `static_cast` не спасёт программу от UB.

### `reinterpret_cast`

`reinterpret_cast` применяется для низкоуровневых преобразований указателей, ссылок и некоторых целочисленных представлений. Его не следует понимать как «безопасно взять те же биты и получить значение другого типа».

```cpp
long long value = 5757;
double& wrong = reinterpret_cast<double&>(value);
```

Приведение может скомпилироваться, но оно не создаёт объект `double`. В памяти по-прежнему находится `long long`. Чтение `wrong` как `double` нарушает правила доступа к объекту и приводит к UB — даже если `long long` и `double` на данной платформе имеют одинаковый размер.

Для копирования битового представления между одинаковыми по размеру подходящими типами начиная с C++20 предназначен `std::bit_cast`:

```cpp
std::uint64_t bits = 0;
double value = std::bit_cast<double>(bits);
```

Это создаёт отдельный объект результата и не обращается к исходному объекту через ложный тип. При этом получившееся представление всё равно должно быть допустимо для целевого типа.

`reinterpret_cast` не снимает `const`. Если преобразование требует одновременно изменить константность, это уже отдельная и потенциально опасная операция.

### `const_cast`

`const_cast` добавляет или убирает `const` и `volatile` у указателя или ссылки:

```cpp
int value = 1;
const int& read_only = value;
int& writable = const_cast<int&>(read_only);

writable = 2; // допустимо: исходный объект value не был const
```

Если исходный объект действительно объявлен константным, попытка изменить его после снятия `const` приводит к UB:

```cpp
const int value = 1;
int& writable = const_cast<int&>(value);

// writable = 2; // UB
```

Сам `const_cast` может скомпилироваться. Проблема возникает при модификации объекта, который был создан как константный. Обычно необходимость снимать `const` указывает на неудачно выбранный интерфейс, хотя такое приведение встречается при работе со старыми API.

### Приведение в стиле C

```cpp
double value = 3.5;
int x = (int)value;
```

Приведение в стиле C пытается подобрать один из нескольких механизмов C++, включая комбинации `static_cast`, `const_cast` и `reinterpret_cast`. По короткой записи трудно понять, какое именно опасное действие разрешил программист. Поэтому в C++ обычно предпочитают именованные приведения: их проще искать в коде и проверять при ревью.

### `dynamic_cast`

`dynamic_cast` используется в иерархиях полиморфных классов для проверяемого преобразования указателей и ссылок. В отличие от `static_cast`, он может проверить фактический тип объекта во время выполнения. Подробно этот механизм рассматривается после наследования и виртуальных функций, поскольку без этих понятий его правила будут непонятны.

## §2.8. Стадии сборки

Упрощённо сборку программы C++ делят на четыре стадии: препроцессинг, компиляцию, ассемблирование и линковку. На практике компилятор запускает их одной командой, но понимание границ помогает разбирать сообщения об ошибках.

### 1. Препроцессинг

Препроцессор обрабатывает директивы, начинающиеся с `#`:

```cpp
#include <iostream>
#define BUFFER_SIZE 1024

#if defined(DEBUG)
    // Этот фрагмент останется только в отладочной конфигурации.
#endif
```

`#include` в общих чертах подставляет содержимое найденного файла в текущий исходный файл. После обработки получается единица трансляции — большой текст C++, который затем анализирует компилятор.

Обычно запись с кавычками сначала ищет файл относительно текущего исходника, а запись с угловыми скобками использует настроенные каталоги заголовков:

```cpp
#include "project/header.hpp"
#include <vector>
```

Точные пути и порядок поиска определяются реализацией и параметрами сборки. Угловые скобки не означают, что файл обязательно физически лежит внутри одной конкретной папки стандартной библиотеки.

Только препроцессинг в GCC можно запустить ключом `-E`:

```bash
g++ -E main.cpp
```

### 2. Компиляция

Компилятор разбирает токены и грамматику C++, ищет имена, проверяет типы, выполняет шаблонные подстановки и преобразует программу в более низкоуровневое представление. При включённой оптимизации на этом же пути код существенно преобразуется.

Ключ `-S` просит GCC остановиться после получения ассемблерного текста:

```bash
g++ -S main.cpp
```

Обычно результатом будет файл вроде `main.s`. Конкретные промежуточные стадии и форматы являются деталями компилятора, поэтому не каждая реализация обязана буквально создавать файл `.s` при обычной сборке.

### 3. Ассемблирование

Ассемблер превращает ассемблерный код в объектный файл с машинными инструкциями:

```bash
g++ -c main.cpp
```

Обычно команда создаёт `main.o` или `main.obj`. Объектный файл ещё не обязательно можно запустить. Он содержит машинный код, таблицы символов, информацию для линкера и другие служебные данные.

Если функция вызвана, но определена в другом объектном файле, компилятор может оставить ссылку на соответствующий символ. Никакого обязательного «блока на месте вызова» нет: точная форма вызова и перемещений зависит от ABI, компилятора и оптимизаций.

### 4. Линковка

Линкер объединяет объектные файлы и библиотеки, связывает ссылки на внешние символы с их определениями и создаёт исполняемый файл:

```bash
g++ main.o helpers.o -o program
```

Линкер не обязан буквально подставлять тело каждой функции в место вызова. Обычно он определяет адреса символов и исправляет необходимые ссылки. Встраивание тела функции (`inlining`) — отдельная оптимизация, которая может происходить раньше или во время link-time optimization.

Типичные ошибки линковки:

- **undefined reference** — функция или переменная была объявлена и использована, но подходящее определение не найдено;
- **multiple definition** — найдено несколько несовместимых определений одной сущности.

Расширение исполняемого файла зависит от платформы и выбранного имени. `.out` не является обязательным форматом C++; в Linux файл может вообще не иметь расширения, а в Windows обычно используется `.exe`.

### Отдельная компиляция

Каждый `.cpp` вместе с подключёнными заголовками обычно превращается в отдельную единицу трансляции:

```text
main.cpp    ──> main.o    ┐
helpers.cpp ──> helpers.o ├──> program
parser.cpp  ──> parser.o  ┘
```

Из-за этого объявление функции помещают в заголовочный файл, который видят разные `.cpp`, а определение обычной функции — в один исходный файл. Нарушение этого разделения часто объясняет ошибки на стадии линковки.

### Санитайзеры

Санитайзеры добавляют в программу проверки, которые выполняются во время работы. Например:

- AddressSanitizer помогает искать выход за границы выделенной памяти, use-after-free и некоторые другие ошибки доступа;
- UndefinedBehaviorSanitizer обнаруживает часть операций с неопределённым поведением;
- LeakSanitizer помогает искать утечки памяти.

Пример сборки с GCC или Clang:

```bash
g++ -std=c++20 -Wall -Wextra -g \
    -fsanitize=address,undefined main.cpp -o program
```

Санитайзеры не «обходят» UB и не превращают ошибочную программу в корректную. Они вставляют дополнительные проверки и стараются остановить программу рядом с обнаруженной проблемой. Покрываются не все виды UB, а результат зависит от того, была ли опасная ветвь действительно выполнена. Поэтому успешный запуск под санитайзером не доказывает отсутствие ошибок.

Для диагностики полезно сочетать предупреждения компилятора, санитайзеры, тесты и внимательное соблюдение правил времени жизни, типов и границ объектов.
