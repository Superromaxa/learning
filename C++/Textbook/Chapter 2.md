# II. Составные типы в C++

## §2.1. Указатели

У объекта есть адрес в памяти. Оператор `&` берёт адрес, оператор `*` обращается к объекту по адресу:

```cpp
int x = 5;
int* p = &x; // p хранит адрес x
*p = 7;     // теперь x == 7
```

`int*` — тип указателя на `int`. Звёздочка в объявлении (`int* p`) — часть записи типа, а в `*p` — операция разыменования. При объявлении нескольких указателей звёздочку нужно писать для каждого: `int *p, *q;`.

Адреса обычно печатаются в шестнадцатеричной форме. Размер указателя зависит от платформы (часто 8 байт в 64-битной программе), а не от размера объекта, на который он указывает.

Операции с указателями:

- `p + n`, `p - n`, `++p`, `--p` сдвигают указатель на **элементы**, а не на отдельные байты. Для `int*` сдвиг на 1 соответствует `sizeof(int)` байтам.
- Разность двух указателей на элементы одного массива имеет тип `std::ptrdiff_t` и показывает число элементов между ними.
- Указатели можно присваивать и сравнивать. Сравнение на равенство доступно шире, а упорядочивающее сравнение имеет смысл прежде всего для элементов одного массива.
- Адрес самого указателя имеет тип «указатель на указатель»: `int** pp = &p;`.

Операции `&` и `*` могут взаимно сокращаться, если обращение допустимо: `*&*&*&p` обозначает `p`. Выражение `*p` — lvalue, через него можно менять объект. Для обычного объекта `&p` — prvalue с его адресом. Оператор взятия адреса применяется к подходящему lvalue (например, к переменной), но не к произвольному временному значению.

Разыменовывать указатель можно только тогда, когда он указывает на живой объект нужного типа. Указатель на уже уничтоженный объект, `nullptr` и указатель «за концом» массива разыменовывать нельзя. Само увеличение указателя **не** обязательно ошибка: в пределах массива допустим и указатель на элемент сразу после последнего, но обращаться через него к элементу нельзя.

`void*` хранит адрес без информации о типе объекта. Напрямую разыменовать его нельзя: сначала нужно вернуть подходящий тип указателя. `nullptr` — литерал пустого указателя; его тип — `std::nullptr_t`.

Указатели позволяют функции работать с исходными объектами:

```cpp
void swap(int x, int y) {
    int t = x;
    x = y;
    y = t;
}
```

Здесь меняются только локальные копии `x` и `y`; значения у вызывающей стороны останутся прежними.

```cpp
void swap(int* x, int* y) {
    int t = *x;
    *x = *y;
    *y = t;
}

int a = 1, b = 2;
swap(&a, &b); // теперь a == 2, b == 1
```

Во втором варианте функция получает адреса исходных переменных и меняет их значения. В реальном коде аргументы должны быть действительными указателями, не `nullptr`.

## §2.2. Виды памяти

У работающей программы есть память для кода и данных. С точки зрения C++ важнее различать **время жизни** объектов и способ их создания:

- Код программы содержит машинные инструкции.
- Объекты со *статическим временем хранения* существуют всю программу: например, глобальные переменные и локальные переменные с `static`.
- Объекты с *автоматическим временем хранения* обычно создаются при входе в блок и уничтожаются при выходе; на практике часто используют стек.
- Объекты с *динамическим временем хранения* создаются явно во время работы программы и живут до освобождения.

```cpp
int* p = new int{42}; // создан объект int со значением 42
delete p;             // объект уничтожен, память освобождена
p = nullptr;          // старый адрес больше не используем
```

`new` создаёт объект и возвращает указатель на него; `delete` уничтожает объект, созданный обычным `new`. `malloc` из C только выделяет сырой блок памяти и не заменяет создание объекта через `new`. Пары `new`/`delete` и `malloc`/`free` смешивать нельзя.

Если потерять последний указатель на динамический объект до освобождения памяти, возникнет **утечка**. Повторное `delete` того же объекта недопустимо. На практике ручное владение памятью обычно заменяют `std::vector`, `std::string` и умными указателями.

```cpp
void f() {
    static int calls = 0;
    ++calls;
}
```

`calls` создаётся один раз и сохраняет значение между вызовами `f`. Повторное выполнение строки объявления не создаёт новую переменную.

## §2.3. Массивы

Встроенный массив содержит элементы одного типа подряд:

```cpp
int a[10];                  // 10 элементов; локальные int без инициализации
int b[] = {1, 2, 3, 4, 5}; // размер выведен: 5
int c[5] = {1, 2};         // остальные элементы равны 0
int d[5]{};                // все элементы равны 0
```

Локальные массивы обычно размещаются в автоматической памяти, но массив может быть и глобальным, статическим или динамическим. Размер обычного встроенного массива должен быть известен при компиляции (массив переменной длины — не стандартный C++, хотя некоторые компиляторы допускают его как расширение).

Индексация начинается с нуля. Для массива из `N` элементов допустимы индексы от `0` до `N - 1`; `a[-1]` и `a[N]` обращаются вне массива — это UB.

```cpp
int a[] = {10, 20, 30, 40};
int* p = a + 3;

int x = *(a + 2); // x == 30: то же, что a[2]
int y = 2[a];     // y == 30: допустимо, но так обычно не пишут
int z = p[-1];    // z == 30: элемент перед a[3]
```

В большинстве выражений имя массива преобразуется в указатель на первый элемент. Поэтому работают `a + 3` и `*(a + 3)`, но **массив не является указателем**: его нельзя присвоить другому массиву или увеличить через `++a`. `sizeof(a)` даёт размер всего массива в байтах, пока преобразование к указателю не произошло.

Параметр функции, записанный как массив, в объявлении фактически становится указателем: `void f(int a[])` и `void f(int* a)` — одна сигнатура, перегрузить их друг относительно друга нельзя. Размер исходного массива по такому параметру не узнать.

Динамический массив:

```cpp
int* b = new int[100]{};
// работа с b[0] ... b[99]
delete[] b;
```

`b` — указатель, поэтому `sizeof(b)` показывает размер **указателя**, а не всех 100 элементов. Парой к `new[]` служит `delete[]`. Реализация может хранить служебные данные о массиве, но полагаться на их расположение нельзя. Если размер определяется во время работы программы, обычно удобнее `std::vector<int>`.

Многомерный массив и чтение сложных объявлений:

```cpp
int matrix[5][5]; // массив из 5 массивов по 5 int
int* pointers[5]; // массив из 5 указателей на int
int (*row)[5];    // указатель на массив из 5 int
```

Скобки в `int (*row)[5]` важны: без них объявился бы массив указателей. При передаче `int matrix[5][5]` в функцию получается `int (*)[5]`, **не** `int**`. Массив указателей `int* pointers[5]` при такой передаче, наоборот, превращается в `int**`.

## §2.4. Функции и указатели на функции

Функция связывает имя с блоком инструкций. Её можно объявить несколько раз с совместимыми объявлениями, но определение должно соблюдать правило одного определения. В объявлении имена параметров можно не писать:

```cpp
int sum(int, int);          // объявление
int sum(int a, int b) {    // определение
    return a + b;
}
```

При передаче **по значению** создаются копии аргументов. `return` завершает вызов и возвращает результат.

У параметров могут быть значения по умолчанию. После параметра со значением по умолчанию следующие параметры тоже должны иметь такие значения (в пределах одного списка параметров). Существуют и C-подобные вариативные функции с `...`; их аргументы обрабатывают через средства `<cstdarg>`, но в C++ обычно предпочитают более безопасные альтернативы.

Указатель на функцию хранит адрес функции с определённой сигнатурой:

```cpp
bool compare(int x, int y) {
    return x < y;
}

bool (*p)(int, int) = &compare;
bool result = p(1, 2); // result == true
```

Имя функции в подходящем контексте само преобразуется в указатель: `bool (*q)(int, int) = compare;`. Если имя перегружено, нужную перегрузку может подсказать ожидаемый тип указателя; без такого контекста запись `&compare` бывает неоднозначной.

Сложное объявление из исходного конспекта:

```cpp
void (*(*p[10])(int))(int);
```

`p` — массив из 10 указателей на функции. Каждая такая функция принимает `int` и возвращает указатель на другую функцию; та тоже принимает `int`, но возвращает `void`. Скобки помогают читать объявление от имени `p` наружу.

## §2.5. Ссылки

Ссылка — другое имя уже существующего объекта. Обычную lvalue-ссылку нужно сразу связать с объектом; позже «перенаправить» её нельзя.

```cpp
int x = 4;
int& r = x;
r = 9; // теперь x == 9
```

Нельзя создать ссылку на `void`, массив ссылок или ссылку на ссылку как отдельный тип. При этом записи с несколькими `&` могут возникать в шаблонах и сворачиваются по правилам языка. Обычная `T&` не связывается с временным rvalue; `const T&` и `T&&` имеют другие правила.

Передача по ссылке позволяет менять исходный объект без копирования. Представлять ссылку как указатель иногда удобно, но стандарт не требует реализации ссылки именно через указатель. Время жизни объекта также не определяется количеством его имён.

Перегрузки `void f(int)` и `void f(int&)` объявить можно, но вызов с обычной переменной `int` будет неоднозначным.

В исходном варианте обмена была ошибка:

```cpp
void swap(int& x, int& y) {
    int t = x;
    x = y;
    y = x; // ошибка логики: здесь уже новое x
}
```

После `x = y` старое значение `x` осталось только в `t`. Правильная последняя строка — `y = t;`.

Ссылка может быть результатом функции:

```cpp
int& f(int& x) { return ++x; }

int x = 0;
f(x) = 1;     // меняет сам x
int y = f(x); // y получает копию нового значения x
```

Опасный вариант из исходного конспекта:

```cpp
int& g(int& x) {
    int y = ++x;
    return ++y; // возвращается ссылка на локальную переменную
}
```

`y` уничтожится при выходе из `g`; обращаться к результату `g(x)` нельзя. Компилятор обычно предупредит, но не обязан остановить сборку.

```cpp
// int y = g(x); // скомпилироваться может, но чтение через висячую ссылку — UB
```

Можно объявлять ссылки на указатели, массивы и функции.

## §2.6. Константы

`const` запрещает менять объект **через это имя или этот путь доступа**. Для простого `const int` допустимы чтение и вычисления вроде `c + 1`, но не `c = 2` или `++c`. Константный объект нужно инициализировать.

Для указателей важно, где стоит `const`:

- `const int* p` или `int const* p` — указатель на `const int`: через `p` нельзя менять число, но сам `p` можно переназначить.
- `int* const p` — константный указатель на изменяемый `int`: адрес переназначить нельзя, число через `p` менять можно.

```cpp
int x = 0;
int y = 1;
int* p = &x;

const int* pc = p; // через pc можно читать x
// *pc = 1;        // ошибка компиляции: менять x через pc нельзя
pc = &y;           // сам указатель pc менять можно

int* const cp = &x;
// cp = &y;        // ошибка компиляции: cp всегда указывает на x
*cp = 1;           // x теперь равен 1

// int* p2 = pc;   // ошибка компиляции: так потерялась бы защита const
```

Если сам `x` не объявлен константным, его всё ещё можно менять через `x` или `int*`. Запрет действует на конкретный путь доступа через `const int*`.

Добавить `const` сразу на двух уровнях указателей не всегда можно:

```cpp
const char x = 'a';
char* p = nullptr;
// const char** q = &p; // ошибка компиляции
```

Если бы последняя строка была разрешена, продолжение могло бы выглядеть так:

```cpp
// *q = &x;  // p теперь указывал бы на константный x
// *p = 'b'; // попытка изменить x через p: UB
```

Поэтому преобразование `char**` в `const char**` запрещено.

Константная ссылка:

```cpp
int x = 0;
const int& r = x; // через r менять x нельзя
// int& const rc = x; // ошибка: сама ссылка не переназначается и const здесь не нужен
// int& r1 = r;       // ошибка: через r можно только читать
x = 1;               // сам x остаётся изменяемым
```

`const T&` может связываться с временным объектом. При прямом связывании время жизни временного объекта часто продлевается до времени жизни ссылки, но при **передаче в функцию** — только до конца полного выражения вызова:

```cpp
void print(const std::string& text);
print("abc"); // временная std::string доступна во время вызова
```

Обычная неконстантная ссылка не позволяет незаметно изменить временный результат преобразования:

```cpp
void g(std::size_t& y) { ++y; }
int x = 0;
// g(x); // ошибка компиляции: int нельзя привязать к std::size_t& через временный объект
```

## §2.7. Приведения типов

Основные формы: `static_cast`, `reinterpret_cast`, `const_cast`, C-style cast и `dynamic_cast`.

**`static_cast`** — явное преобразование, которое проверяется по правилам языка:

```cpp
int x = 3;
double d = static_cast<double>(x); // d == 3.0
void* raw = static_cast<void*>(&x); // адрес сохранён без типа int
```

`static_cast` не означает, что любое преобразование безопасно: например, при сужении числа может потеряться информация.

**`reinterpret_cast`** позволяет переосмыслить указатель или ссылку как другой тип. Это не операция безопасного преобразования значения:

```cpp
long long y = 5757;
// double d = reinterpret_cast<double&>(y); // читать y как double нельзя: UB
```

Само приведение может скомпилироваться; проблема возникает при обращении к объекту через неподходящий тип. Для копирования битового представления в другой тип существуют отдельные способы, например `std::bit_cast` (C++20) при выполнении его условий.

**`const_cast`** меняет квалификацию `const` у указателя или ссылки. Менять через него объект, который *изначально был объявлен константным*, нельзя:

```cpp
const int c = 1;
int& cc = const_cast<int&>(c);
// cc = 2; // UB: c — действительно константный объект
```

Если исходный объект неконстантный, но доступен через `const int&`, снять `const` и изменить его можно — хотя чаще лучше передать изменяемую ссылку сразу.

**C-style cast** может выполнять разные виды преобразований, включая менее безопасные; по записи труднее понять намерение:

```cpp
double d = (double)x; // преобразование в стиле C; x должен быть объявлен ранее
```

Обычно предпочитают именованные формы `*_cast`.

**`dynamic_cast`** применяется к указателям и ссылкам на полиморфные классы для проверяемого приведения по иерархии наследования; подробнее — в главах об ООП.

## §2.8. Стадии сборки

Упрощённая схема сборки — четыре этапа:

1. **Препроцессинг.** Обрабатываются `#include`, `#define`, `#if`, `#pragma` и другие директивы. Для `#include <...>` обычно ищут в настроенных системных каталогах, для `#include "..."` сначала ищут рядом с исходным файлом; точные правила зависят от компилятора и его настроек. Результат остаётся текстом C++.
2. **Компиляция.** Исходный C++ анализируется и переводится в код следующего уровня; с ключом `g++ -S` можно получить ассемблерный файл `.s`.
3. **Ассемблирование.** Ассемблерный код превращается в объектный файл (`.o` или `.obj`) с машинным кодом и информацией для линкера.
4. **Линковка.** Линкер связывает объектные файлы и библиотеки, разрешает ссылки на внешние символы и создаёт исполняемый файл. Расширение выходного файла зависит от платформы (`.exe`, например, в Windows); `.out` не обязательно.

**Санитайзеры** добавляют проверки во время выполнения и помогают *обнаружить* некоторые ошибки, но не «обходят» UB и не гарантируют поиск всех его случаев. Например, AddressSanitizer помогает находить ошибки доступа к памяти, UndefinedBehaviorSanitizer — часть других нарушений.
