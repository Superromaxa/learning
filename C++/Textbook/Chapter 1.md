# I. Введение в C++

## §1.1. Терминал и работа в нём

Команды терминала:

| Команда | Назначение |
| --- | --- |
| `cd` | Перейти в другую директорию. |
| `chmod` | Изменить права доступа к файлу. |
| `Ctrl+W` | Стереть слово в командной строке. |
| `Ctrl+U` | Стереть строку в командной строке. |

Этапы сборки и диагностика с `g++`:

| Ключ | Назначение |
| --- | --- |
| `-E` | Выполнить только препроцессинг. |
| `-S` | Остановиться после генерации ассемблерного кода. |
| `-c` | Создать объектный файл без линковки. |
| `-fsanitize=address` | Включить AddressSanitizer для поиска ошибок работы с памятью (обычно вместе с `-g`). |

## §1.2. Типы и поддерживаемые операции

C++ — язык со статической типизацией: типы выражений известны на этапе компиляции.

### Встроенные типы

- Целочисленные: `int` (часто 4 байта), `long` (4 или 8 байт в зависимости от платформы), `long long` (не менее 8 байт), `short`, `char`, `bool`. Модификаторы `signed` и `unsigned` применимы к целочисленным типам, но не к `bool`.
- Целочисленные типы заданной ширины: `std::int8_t`, `std::int16_t`, `std::int32_t`, `std::int64_t` из `<cstdint>` (при наличии соответствующей ширины на платформе).
- `std::byte` из `<cstddef>` — тип для представления байта, не обычное число.
- `std::size_t` — беззнаковый тип для размеров объектов и индексов; размер контейнера обычно возвращается в этом типе.
- С плавающей точкой: `float`, `double`, `long double`. При обычном 32-битном `int` все его значения точно представимы в типичном `double`; свойства типов зависят от реализации.

### Стандартные типы и контейнеры

- `std::string` — строка. Операции: `operator[]`, `at(size_t)`, `operator+`, `push_back(char)`, `pop_back()`, `front()`, `back()`, `size()`, `clear()`, `reserve()`, `resize(size_t, char)`, `capacity()`. `c_str()` возвращает последовательность с завершающим нулевым символом; этот символ не учитывается в `size()`.
- `std::vector<T>` — динамический массив элементов типа `T`. Операции: `operator[]`, `at(size_t)`, `push_back(const T&)`, `pop_back()`, `front()`, `back()`, `size()`, `shrink_to_fit()`, `reserve()`, `resize(size_t, const T&)`, `capacity()`.
- `std::list` — двусвязный список; `std::forward_list` — односвязный список.
- `std::deque` — двусторонняя очередь.
- `std::stack`, `std::queue`, `std::priority_queue` — адаптеры контейнеров.
- `std::map<Key, Value>` — упорядоченная таблица пар ключ–значение; поиск, вставка и удаление обычно выполняются за `O(log n)`. Операции: `operator[]` (при отсутствии ключа создаёт значение по умолчанию), `at(key)`, `find(key)`, `insert(pair)`, `erase(key)`.
- `std::multimap<Key, Value>` — упорядоченная таблица, допускающая одинаковые ключи. `lower_bound(key)` возвращает первый элемент с ключом не меньше `key`, `upper_bound(key)` — первый элемент с ключом больше `key`.
- `std::unordered_map<Key, Value>` — хеш-таблица; элементы не упорядочены. Поиск в среднем занимает `O(1)`.
- `std::set`, `std::multiset`, `std::unordered_set` — множества; `multiset` допускает повторы, `unordered_set` использует хеширование.
- `std::istream`, `std::ostream` — типы потоков ввода и вывода.

### Литералы и системы счисления

**Литерал** — запись значения определённого типа: `5`, `0.2`, `"abc"`, `'#'`. Суффикс может уточнять тип:

```cpp
5u    // unsigned int
0.2f  // float
```

Префиксы целочисленных литералов:

```cpp
0x2A    // шестнадцатеричная запись: 42
052     // восьмеричная запись: 42
0b101010 // двоичная запись: 42 (начиная с C++14)
```

## §1.3. Объявления и определения

Программа содержит объявления переменных, функций, классов, структур и других сущностей. В глобальной области видимости допустимы объявления, а не произвольные инструкции.

**Пространство имён (`namespace`)** позволяет разделять одноимённые сущности. Оператор `::` указывает область видимости: `std::cout` — квалифицированное имя; `::x` обращается к глобальному `x`.

**`using`** вводит имя из другого пространства имён в текущую область или задаёт псевдоним типа. Например, `using std::cout;` и `using Size = std::size_t;`. `using namespace ...` привлекает сразу множество имён и может привести к неоднозначности; ошибка возникнет при соответствующем неоднозначном обращении, а не обязательно в самой строке `using`.

Ключевые слова C++ имеют закреплённый смысл и не могут служить обычными идентификаторами.

### Область видимости

- Имя доступно в своей области видимости и, если не скрыто, во вложенных областях.
- При поиске неквалифицированного имени сначала рассматривается ближайшая подходящая область. Локальное имя может скрывать глобальное.
- Повторное объявление одного имени в одной области подчиняется правилам языка: некоторые повторные объявления допустимы, конфликтующие определения — нет.
- Область видимости имени переменной начинается уже после её объявления, в том числе в её инициализаторе:

```cpp
int x = x; // синтаксически допустимо, но чтение неинициализированного x недопустимо
```

Здесь не получается «случайное число», на которое можно рассчитывать: чтение неопределённого значения для обычного `int` приводит к неопределённому поведению.

### Правило одного определения (One Definition Rule, ODR)

- Сущность можно объявлять несколько раз, но её определения должны соблюдать ODR. В рамках одной единицы трансляции повторное определение обычно недопустимо.
- Некоторые определения (например, определения класса в разных единицах трансляции) могут повторяться при выполнении требований ODR; недостаточно лишь общего сходства текста.
- Определение одновременно является объявлением.

```cpp
void f(int x);   // объявление функции
void f(int x) {} // определение функции

extern int n;    // объявление переменной без определения
int n = 0;       // определение и инициализация
```

В `int n = 0;` знак `=` обозначает инициализацию, а не оператор присваивания уже существующей переменной. `extern` без инициализатора обычно означает лишь объявление; детали зависят от контекста.

## §1.4. Выражения и операции

Внутри функции, помимо объявлений, доступны выражения и управляющие конструкции. **Выражение** вычисляет значение, может вызывать побочные эффекты и составляться из литералов, имён, вызовов и операций.

Основные операции: `+`, `-`, `*`, `/`, `%`, `>`, `<`, `>=`, `<=`, `&`, `|`, `^`, `<<`, `>>`, `&&`, `||`, `==`, `!=`, `<=>` (последний — с C++20). Составные присваивания: `+=`, `-=`, `*=`, `/=`, `%=`, `>>=`, `<<=`, `&=`, `|=`, `^=`.

Категории значений включают **lvalue** и **rvalue**; это не просто деление по признаку «можно ли присвоить». Например, `const int` может быть lvalue, хотя присвоение ему запрещено.

**Ассоциативность** определяет группировку операций одинакового приоритета: многие бинарные операции группируются слева направо, присваивание — справа налево. Перегрузка оператора не меняет его приоритет и ассоциативность. Группировка не равна порядку вычисления операндов.

`&&` вычисляет **сначала левый** операнд; если он ложен, правый не вычисляется. `||` также начинает с левого и пропускает правый, если левый истинен.

### Инкремент и декремент

Префиксные формы `++a`, `--a` изменяют объект и возвращают ссылку на изменённый объект (для встроенных типов — lvalue). Постфиксные `a++`, `a--` изменяют объект, но значение выражения соответствует прежнему значению (для встроенных типов — prvalue).

```cpp
int a = 3;
int before = a++; // before == 3, a == 4
int after = ++a;  // after == 5, a == 5
```

`++a++` для встроенного `int` некорректно: постфиксная операция группируется первой, а её результат нельзя изменить префиксным `++`.

При лексическом анализе обычно выбирается максимально длинная последовательность символов, образующая допустимый токен (правило maximal munch).

### Условный оператор

```cpp
condition ? expression_if_true : expression_if_false
```

Вычисляется `condition`, затем только одна выбранная ветвь. Тип результата определяется правилами преобразований на этапе компиляции; типы ветвей **не обязаны совпадать**:

```cpp
f(a ? 1 : 0.5); // условное выражение имеет тип double
```

### Оператор запятая

`(left, right)` сначала вычисляет левый операнд, затем правый; результатом является правый операнд. Не каждая запятая в программе — оператор: в `f(x, y)` она разделяет аргументы.

### `sizeof`

`sizeof` возвращает размер типа или выражения в байтах типа `char` как значение `std::size_t`. Обычно операнд-выражение не вычисляется. Для вектора размер самого объекта и число его элементов — разные величины:

```cpp
sizeof(v) // размер объекта std::vector в памяти
v.size()  // количество элементов
```

Приоритет операторов задаётся правилами языка (удобная справочная таблица — cppreference). Он не задаёт общий порядок вычисления: в `f() * g() + h()` порядок вызовов может различаться. Неопределённый порядок не означает, что выражение обязательно некорректно.

## §1.5. Управляющие конструкции

### `if`

```cpp
if (condition1) {
    // ветвь при истинном condition1
} else if (condition2) {
    // ветвь при ложном condition1 и истинном condition2
} else {
    // ветвь при ложных condition1 и condition2
}
```

Без фигурных скобок ветвью является ровно одна следующая инструкция. Начиная с C++17 возможна инициализация перед условием: `if (auto it = m.find(key); it != m.end()) { /* ... */ }`.

### `switch`

```cpp
switch (value) {
    case 1:
        // действия для 1
        break;
    case 2:
        // действия для 2
        break;
    default:
        // если ни одна метка не совпала
}
```

Условие `switch` имеет целочисленный или перечислимый тип. Без `break` выполнение может перейти к следующим меткам (`fallthrough`). `default` применяется при отсутствии совпавшего `case`.

### Циклы

```cpp
while (condition) {
    // проверка перед каждой итерацией
}

do {
    // тело выполняется хотя бы один раз
} while (condition);

for (initialization; condition; expression) {
    // тело цикла
}
```

В `for` сначала выполняется инициализация, затем проверяется условие. Если оно истинно, выполняются тело и завершающее выражение, после чего условие проверяется снова.

- `break` прекращает выполнение ближайшего цикла или `switch`.
- `continue` переходит к следующей итерации ближайшего цикла (в `for` перед новой проверкой выполняется завершающее выражение).
- `goto label;` передаёт управление к метке `label:` в той же функции; переходы ограничены правилами инициализации объектов.

## §1.6. Ошибки и неопределённое поведение

C++ обычно компилируют в исполняемую программу. Полезно различать ошибки сборки, ошибки во время выполнения и семантику некорректной программы.

### Ошибки компиляции и сборки

- Лексический анализ выделяет токены; синтаксический анализ проверяет грамматику; семантический анализ проверяет, в частности, имена и типы.
- Диагностика может возникнуть на любом из этих этапов. Ошибки линковки (например, отсутствие определения вызванной функции) относятся к следующему этапу сборки.
- **Предупреждение** сообщает о возможной проблеме и само по себе обычно не останавливает сборку. Предупреждение может указывать и на реальную ошибку программы.
- `-Wall` включает группу предупреждений GCC; не буквально *все* предупреждения. Конкретное предупреждение можно включить, например, через `-Wunused-value`. Часто добавляют `-Wextra`.

### Ошибки во время выполнения

Примеры наблюдаемых последствий: аварийное завершение с `segmentation fault`, вызов `abort`, ошибка деления на ноль. Само наблюдаемое сообщение не всегда описывает точную первопричину: нарушение доступа к памяти или целочисленное деление на ноль в исходной программе, например, имеют неопределённое поведение.

### Неопределённое поведение (undefined behavior, UB)

Стандарт не накладывает требований на результат выполнения при UB. Частые причины: выход за границы массива, чтение неинициализированного `int`, переполнение знакового целого, некоторые неупорядоченные изменения одной переменной в выражении.

Пример из исходного конспекта:

```cpp
for (int i = 0; i < 300; ++i) {
    std::cout << i << ' ' << i * 12345678 << '\n';
}
```

При типичном 32-битном `int` произведение `174 * 12345678` уже превышает `INT_MAX`. Поэтому в этой итерации возникает UB; **достоверного вывода всей программы нет**. Оптимизатор может исходить из того, что корректная программа не допускает UB, и преобразовать даже окружающий цикл неожиданным образом. Для расчёта без такого переполнения достаточно расширить тип до умножения, например `1LL * i * 12345678` (здесь максимальное произведение помещается в `long long`).

### Неуточнённый порядок вычисления

Когда стандарт допускает несколько порядков вызовов, программа может оставаться корректной, но её наблюдаемый результат при побочных эффектах будет зависеть от выбранного порядка. Например, в `f() * g() + h()` нельзя просто по расположению функций слева направо заключить, какая вызовется первой. Это следует отличать от UB.
