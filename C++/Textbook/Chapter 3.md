# III. Введение в ООП

## §3.1. Классы и структуры

ООП позволяет описать свой тип: какие данные хранит объект и какие операции с ним доступны. В C++ для этого используют `class` и `struct`. Оба могут содержать поля, методы и вложенные типы; основные различия — доступ по умолчанию и наследование по умолчанию.

```cpp
class Empty {};
Empty object;
```

Поля задают состояние объекта:

```cpp
struct Point {
    int x;
    double y;
};

Point p{1, 2.7}; // p.x == 1, p.y == 2.7
```

Это **агрегатная инициализация**. В исходном конспекте для неё был указан `class C` с закрытыми по умолчанию полями; `C c{1, 2.7}` для такого класса не сработает. В примере выше использована `struct`, где поля открыты.

Если локальный объект создать без инициализации полей, чтение таких полей может быть недопустимым. Значения можно задать прямо в объявлении:

```cpp
struct Point {
    int x = 0;
    double y = 3.14;
};

Point p; // p.x == 0, p.y == 3.14
```

К полю обращаются через `.`: `p.x`. Перегрузить оператор `.` нельзя. Поля размещаются с учётом правил расположения и выравнивания; между ними могут быть пропуски. Для обычной структуры с `int` и `double` размер часто составляет 16 байт, но точное значение зависит от платформы. Не следует читать сырую память объекта как другой тип только потому, что известен предполагаемый сдвиг поля.

Метод — функция, объявленная в классе. Её можно определить сразу или отдельно через квалифицированное имя:

```cpp
class Counter {
    int value = 0;

public:
    void increment();
    int get() const { return value; }
};

void Counter::increment() {
    ++value;
}
```

У нестатического метода есть доступ к объекту, для которого он вызван. `this` — указатель на этот объект; поле можно написать как `this->value`. `this` не является явным первым параметром в обычной записи объявления метода.

Внутри класса можно объявить вложенный класс или структуру, а класс можно объявить и внутри функции:

```cpp
class C {
    struct S {
        char c;
    } a; // поле a имеет тип C::S
};
```

## §3.2. Модификаторы доступа

- `public` — член доступен извне класса.
- `private` — член доступен методам и друзьям класса, но не обычному внешнему коду.
- `protected` — доступен также в некоторых контекстах наследования; подробнее в следующей главе.

У `class` доступ по умолчанию `private`, у `struct` — `public`. Секции доступа могут повторяться и располагаться в любом порядке. Метод, определённый **вне** тела класса через `C::method`, сохраняет доступ к закрытым членам `C`.

`reinterpret_cast` не делает закрытое поле законно доступным. Пытаться добраться до него через предполагаемый адрес и устройство памяти ненадёжно и может привести к UB.

## §3.3. Функции-друзья

Друга объявляют внутри класса словом `friend`. Он получает доступ к закрытым членам, но не становится методом:

```cpp
class Box {
    int value = 5;

    friend int read(const Box& box);
};

int read(const Box& box) {
    return box.value; // доступ разрешён: read — друг Box
}
```

Дружественную функцию можно и определить прямо внутри класса. Дружественным может быть целый класс:

```cpp
class C {
    friend class CC;
    int secret = 0;
};
```

Методы `CC` получат доступ к закрытым членам `C`. Дружба не наследуется и не действует в обратную сторону автоматически.

## §3.4. Конструкторы и деструкторы

### §3.4.1. Конструктор

Конструктор создаёт объект в допустимом состоянии. Его имя совпадает с именем класса, а возвращаемый тип не указывается.

```cpp
class Complex {
    double re = 0;

public:
    Complex(double r) {
        re = r; // сначала re получает 0, затем ему присваивается r
    }
};

Complex c(1.0);
Complex c1 = 2.0;
Complex c2{3.0};
Complex c3 = {4.0};
```

Такой конструктор допускает неявное преобразование из `double`; `explicit` запретил бы строки вида `Complex c1 = 2.0` и `Complex c3 = {4.0}`. Поле удобнее инициализировать сразу, через **список инициализации членов**:

```cpp
Complex(double r) : re(r) {}
```

Это особенно важно для `const`-полей, ссылок и сложных объектов. Поля инициализируются **в порядке их объявления в классе**, а не в порядке записи в списке.

Если пользователь не объявил конструкторы, компилятор может неявно объявить конструктор по умолчанию. Однако его использование может оказаться запрещено, если какое-то поле нельзя инициализировать. Явная запись `Complex() = default;` просит компилятор создать такой конструктор; она не исправит невозможность инициализировать обязательное поле-ссылку без значения.

Инициализация списком и `std::initializer_list` (C++11):

```cpp
String s = {'a', 'b', 'c'};

// В объявлении класса String:
String(std::initializer_list<char> chars);
```

При инициализации фигурными скобками подходящие конструкторы с `std::initializer_list` получают приоритет, но это не значит, что **любой** вызов с `{}` обязательно выберет такой конструктор. У `std::initializer_list` есть `begin()` и `end()`; элементы списка доступны для чтения.

**Конструктор копирования** создаёт новый объект из другого объекта того же класса. Для класса, который владеет динамическим массивом, копирование должно создать свой массив:

```cpp
String(const String& other)
    : arr(new char[other.cap]), sz(other.sz), cap(other.cap) {
    std::memcpy(arr, other.arr, sz + 1);
}
```

Это фрагмент конструктора: предполагаются поля `arr`, `sz`, `cap`, достаточная ёмкость `other.cap` и нулевой символ после `sz` символов. `std::memcpy` годится здесь, потому что **новый** массив не пересекается с исходным. Для пересекающихся областей используют `std::memmove`.

Аргумент берут по ссылке: передача по значению сама потребовала бы копирования `String` и вызвала бы рекурсию. Компилятор может неявно объявить конструктор копирования, но он бывает удалённым или неприменимым; для владеющего сырого указателя стандартное копирование только скопирует адрес, а не данные.

**Copy-on-write (COW)** — подход, при котором несколько объектов разделяют данные до первой записи. Одного конструктора копирования «по умолчанию» для безопасного COW недостаточно: нужны учёт совместного владения и отделение данных перед изменением.

**Делегирующий конструктор** вызывает другой конструктор того же класса в своём списке инициализации:

```cpp
Complex() : Complex(0.0) {}
```

Вызов `this->Complex()` в теле конструктора не заменяет делегирование. Нежелательную перегрузку можно запретить через `= delete`.

### §3.4.2. Деструктор

Деструктор вызывается при уничтожении объекта. Локальные объекты обычно уничтожаются при выходе из области видимости в порядке, обратном завершению их создания. После тела деструктора члены уничтожаются автоматически в обратном порядке объявления.

```cpp
class Buffer {
    char* data;

public:
    explicit Buffer(std::size_t n) : data(new char[n]) {}
    ~Buffer() { delete[] data; }
};
```

Деструктор освобождает массив, которым владеет `Buffer`. Обращаться к полям во время выполнения тела деструктора можно. Но ручное повторное уничтожение объекта, которым программа больше не владеет, недопустимо.

Для автоматических объектов момент уничтожения задаётся областью видимости, для динамических — владельцем и операцией освобождения, для статических — завершением программы. В обычном C++ нет автоматического сборщика мусора, который заменял бы эти правила.

## §3.5. Оператор присваивания

Присваивание меняет **уже существующий** объект:

```cpp
String s;
s = other; // это присваивание, а не создание s
```

Если не объявить оператор присваивания, компилятор может создать его сам, но для класса с владеющим указателем простое копирование полей опасно. Один из способов написать присваивание — **copy-and-swap**:

```cpp
String& operator=(const String& other) {
    String copy = other; // создаём отдельную копию
    swap(copy);          // обмениваем содержимое с текущим объектом
    return *this;
}
```

Здесь предполагается метод `swap`, который без ошибок обменивает всеми ресурсами двух `String`. При выходе из функции `copy` уничтожит старое содержимое текущего объекта. Такой код справляется и с `s = s`. Возврат `String&` позволяет цепочку `a = b = c` без лишней копии.

Вариант с передачей аргумента по значению:

```cpp
String& operator=(String other) {
    swap(other);
    return *this;
}
```

Копия создаётся при передаче `other` (или объект перемещается, если это поддерживается); дальше логика та же.

### §3.5.1. Правило трёх

Если класс вручную управляет ресурсом и ему нужен собственный деструктор, конструктор копирования или копирующее присваивание, обычно нужно продумать **все три**. Иначе один из автоматически созданных методов может, например, скопировать сырой указатель, после чего два объекта попытаются удалить один массив. Для современного C++ есть также правило пяти (с перемещением) и правило нуля (передать владение готовым типам).

## §3.6. Константные и статические члены, `explicit`

Неконстантный метод нельзя вызвать у `const`-объекта: он потенциально меняет его состояние. Метод, который не должен менять наблюдаемое состояние объекта, помечают `const`:

```cpp
class String {
public:
    char& operator[](std::size_t i);
    const char& operator[](std::size_t i) const;
};
```

Такой набор перегрузок позволяет менять символ у обычного объекта и читать его у константного:

```cpp
String s = "abcd";
const String& cs = s;
const char& c = cs[0]; // c ссылается на первый символ s
s[0] = 'b';
assert(c == 'b');     // c теперь видит 'b'
```

Пример предполагает работающие конструктор и обе версии `operator[]`. Константная ссылка `cs` не делает сам объект `s` константным; его по-прежнему можно менять через `s`.

Поле `mutable` можно изменять даже в `const`-методе — например, для кэша:

```cpp
mutable int cache = 0;
```

Статические поля и методы относятся к классу, а не к отдельному объекту. Обычный `static`-метод не имеет `this`. Инициализация статических полей зависит от их вида: например, `inline static int count = 0;` разрешена внутри класса начиная с C++17; поэтому общий запрет на инициализацию неконстантного статического поля внутри класса неверен.

`explicit` перед конструктором запрещает нежелательное неявное преобразование **к** классу. Оператор преобразования задаёт переход **из** класса в другой тип:

```cpp
explicit operator double() const;
```

С C++11 операторы преобразования *могут* быть `explicit`, но это не обязательное требование.

Начиная с C++11 можно объявлять пользовательские литеральные суффиксы через `operator""`. Возможные параметры зависят от вида литерала: среди них есть `unsigned long long` для целых и `const char*` вместе с длиной для строковых литералов; ими список не исчерпывается.

## §3.7. Перегрузка операторов

Для пользовательского типа можно определить поведение существующих операторов. Нельзя придумать новый знак операции или поменять приоритет и ассоциативность существующего. Некоторые операторы вообще не перегружаются.

Для примеров возьмём комплексное число:

```cpp
class Complex {
public:
    double re = 0;
    double im = 0;

    Complex(double real) : re(real) {}
    Complex(double real, double imag) : re(real), im(imag) {}
};
```

### Сложение

Оператор как метод получает левый операнд через `this`:

```cpp
Complex operator+(const Complex& other) const {
    return Complex(re + other.re, im + other.im);
}
```

Так можно написать `complex + 2`: число справа неявно преобразуется в `Complex`, если конструктор не `explicit`. Но `2 + complex` не найдёт этот метод у `int`. Внешняя функция допускает преобразование обоих аргументов:

```cpp
Complex operator+(const Complex& a, const Complex& b) {
    return Complex(a.re + b.re, a.im + b.im);
}
```

Здесь поля сделаны `public` только для краткости примера. При закрытых полях функция должна пользоваться открытым интерфейсом или быть другом класса. Метод и внешний оператор с одинаковым назначением не следует определять одновременно без продуманного разрешения перегрузок.

Наивный `+=` через обычное сложение создаёт лишний объект:

```cpp
Complex& operator+=(const Complex& other) {
    *this = *this + other;
    return *this;
}
```

Обычно делают наоборот: сначала эффективный `+=`, потом `+` через него:

```cpp
Complex& operator+=(const Complex& other) {
    re += other.re;
    im += other.im;
    return *this;
}

Complex operator+(const Complex& a, const Complex& b) {
    Complex result = a;
    result += b;
    return result;
}
```

Компилятор может убрать копирование локального `result` при возврате (NRVO), но для такого случая это не всегда обязательно.

Для класса с обычным оператором присваивания возможно и странное выражение `a + b = c`: результат `a + b` — временный объект, и присваивание меняет **его**, а не `a` или `b`. Если это нежелательно, копирующее присваивание можно ограничить lvalue-объектами:

```cpp
Complex& operator=(const Complex& other) &;
```

### Ввод и вывод

Левый операнд `<<` для вывода — поток, поэтому оператор обычно делают внешней функцией:

```cpp
std::ostream& operator<<(std::ostream& os, const Complex& c) {
    return os << c.re << " + " << c.im << 'i';
}
```

Поток передают по неконстантной ссылке, потому что вывод меняет его состояние; возвращают тот же поток для цепочек `std::cout << a << b`. Если поля закрыты, используют открытые методы или `friend`. Аналогично определяют `operator>>` для ввода.

### Сравнения

Лексикографическое сравнение сначала проверяет действительную часть, затем мнимую:

```cpp
bool operator<(const Complex& a, const Complex& b) {
    return a.re < b.re || (a.re == b.re && a.im < b.im);
}

bool operator>(const Complex& a, const Complex& b)  { return b < a; }
bool operator<=(const Complex& a, const Complex& b) { return !(a > b); }
bool operator>=(const Complex& a, const Complex& b) { return !(a < b); }
bool operator==(const Complex& a, const Complex& b) {
    return !(a < b) && !(a > b);
}
```

`std::map` по умолчанию использует порядок, основанный на `<`. Однако вариант `==` через два сравнения `<` может дать неожиданный результат для `double` с NaN; для точного покомпонентного равенства лучше сравнивать поля напрямую. Компилятор **не** создаёт автоматически все остальные операторы только потому, что определён `<`.

Начиная с C++20 есть трёхстороннее сравнение `<=>`:

```cpp
auto operator<=>(const Complex& other) const = default;
```

Для полей `double` результатом будет `std::partial_ordering`, **не** `std::weak_ordering`: NaN может быть несравнимым с другими значениями. `= default` сравнивает поля по порядку и может автоматически дать `==`; при ручной реализации `<=>` оператор `==` отдельно не создаётся. Для пользовательских перегрузок и смешанных типов действуют дополнительные правила поиска и переписывания кандидатов — автоматическое получение всех возможных сравнений обещать нельзя.

### Инкремент и вызов как функции

```cpp
Complex& operator++() {
    ++re;
    ++im;
    return *this; // префиксный ++ возвращает изменённый объект
}

Complex operator++(int) {
    Complex copy = *this;
    ++re;
    ++im;
    return copy; // постфиксный ++ возвращает прежнее значение
}
```

Формальный параметр `int` у постфиксного `operator++(int)` отличает его от префиксного; при обычном `obj++` его значение не используют.

```cpp
struct Greater {
    bool operator()(int x, int y) const {
        return x > y;
    }
};

Greater greater;
bool result = greater(3, 2); // result == true
```

Объект с `operator()` можно вызывать как функцию; такой тип называют **функтором**.

## §3.8. Указатели на члены

Указатель на поле отличается от обычного указателя: он описывает **какое поле** брать у объекта заданного класса, но сам по себе не указывает на конкретный объект.

```cpp
struct S {
    int x = 0;
    void f() { ++x; }
};

int S::* p = &S::x;       // указатель на поле x
void (S::* pf)() = &S::f; // указатель на метод f

S s;
s.*p = 3;       // s.x == 3
(s.*pf)();       // s.x == 4

S* ps = &s;
ps->*p = 5;     // s.x == 5
(ps->*pf)();     // s.x == 6
```

Операции `.*` и `->*` связывают указатель на член с конкретным объектом или указателем на объект. Указатель на поле можно мысленно сравнить со смещением, но считать его просто числовым смещением нельзя: представление зависит от класса и реализации.

## §3.9. Перечисления (`enum`)

Перечисление задаёт набор именованных целочисленных констант:

```cpp
enum Color {
    Red, Green, Blue
};

Color c = Red;
int n = Green; // n == 1
```

Если значения не указаны, они начинаются с 0 и увеличиваются на 1. Можно назначить значения явно: `Red = 5, Green = 7, Blue = 9`; после явно заданного значения следующий элемент без числа получает предыдущее значение плюс один. Обычный `enum` неявно преобразуется в целый тип, обратное преобразование не всегда разрешено без явного приведения.

Переменная типа `Color` **не обязана** содержать только один из перечисленных идентификаторов: допустимый диапазон значений связан с базовым целочисленным типом. Размер перечисления тоже не обязан совпадать с размером `int`.

Начиная с C++11 есть перечисления с областью видимости:

```cpp
enum class Color { Red, Green, Blue };

Color c = Color::Red;
// Color wrong = 1; // ошибка компиляции: нет неявного перехода из int
int value = static_cast<int>(Color::Green); // value == 1
```

Имена элементов `enum class` не попадают в окружающую область видимости, и неявного преобразования в `int` нет. Базовый целочисленный тип можно задать явно: `enum class Color : unsigned char { Red, Green, Blue };`. Наследованием от класса эта запись не является.
