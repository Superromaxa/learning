# III. Введение в ООП

## §3.1. Классы и структуры

Объектно-ориентированное программирование позволяет описывать сущности через их состояние и доступные над ним операции. В C++ можно создать пользовательский тип, определить, какие данные будут хранить его объекты, и задать правила работы с ними.

Например, комплексное число удобно представить не двумя независимыми переменными, а одним объектом:

```cpp
struct Complex {
    double real;
    double imaginary;
};
```

`Complex` — тип, а конкретные комплексные числа — его объекты:

```cpp
Complex first{1.0, 2.0};
Complex second{3.0, -1.0};
```

Класс не обязан соответствовать физическому объекту. Он может описывать строку, файловый дескриптор, итератор, блокировку, математическую операцию или любое другое состояние с определёнными правилами использования.

### `class` и `struct`

Пользовательские типы обычно объявляют с помощью `class` или `struct`:

```cpp
class Counter {};
struct Point {};
```

Оба варианта могут содержать поля, методы, конструкторы, вложенные типы и почти все остальные элементы класса. Основные языковые различия заключаются в доступе и наследовании по умолчанию:

- у `class` члены и базовые классы по умолчанию `private`;
- у `struct` — `public`.

По соглашению `struct` часто используют для простых наборов открытых данных, а `class` — для типов, которые скрывают представление и поддерживают свои инварианты. Это соглашение, а не ограничение языка.

Даже пустой класс имеет ненулевой размер:

```cpp
class Empty {};

Empty first;
Empty second;
```

Разные самостоятельные объекты должны иметь разные адреса, поэтому `sizeof(Empty) >= 1`. Это не означает, что в пустом классе обязательно хранится полезный байт данных. Для пустого базового класса и некоторых полей с `[[no_unique_address]]` возможны отдельные оптимизации размещения.

### Поля

Поля, или нестатические члены данных, задают состояние каждого объекта:

```cpp
struct Point {
    int x;
    double y;
};

Point point{1, 2.7};
```

У `point` есть собственные поля `point.x` и `point.y`. Другой объект `Point` будет содержать другой набор значений.

В этом примере работает агрегатная инициализация: значения передаются полям по порядку объявления. Возможность считать класс агрегатом зависит не только от фигурных скобок, но и от устройства класса и версии стандарта. Например, закрытые поля или пользовательские конструкторы обычно не позволяют использовать такую форму как простое перечисление полей.

Если автоматический объект фундаментального типа не инициализирован, читать его значение нельзя. То же относится к его неинициализированным полям:

```cpp
struct Point {
    int x;
    double y;
};

Point point; // x и y не получили определённых значений
// std::cout << point.x; // недопустимое чтение
```

Значения по умолчанию можно задать непосредственно у полей:

```cpp
struct Point {
    int x = 0;
    double y = 3.14;
};

Point point;
```

Теперь `point.x == 0`, а `point.y == 3.14`, если конкретный конструктор не задаст для них другие инициализаторы.

Для доступа к члену объекта используется оператор `.`:

```cpp
point.x = 5;
std::cout << point.y << '\n';
```

Оператор `.` перегрузить нельзя. Для указателя на объект применяется `->`:

```cpp
Point* pointer = &point;
pointer->x = 10;
```

Запись `pointer->x` по смыслу соответствует `(*pointer).x`.

### Методы и `this`

Функция, объявленная внутри класса, называется методом, или нестатической функцией-членом:

```cpp
class Counter {
    int value = 0;

public:
    void increment() {
        ++value;
    }

    int get() const {
        return value;
    }
};
```

Метод вызывается для конкретного объекта:

```cpp
Counter counter;
counter.increment();
std::cout << counter.get() << '\n';
```

> Вывод: `1`.

У нестатического метода есть указатель `this`, который указывает на объект вызова. Поэтому тело `increment` можно записать так:

```cpp
void increment() {
    ++this->value;
}
```

Обычно `this->` опускают, если имя поля и так однозначно. Представление о скрытом первом параметре полезно, но формально `this` не записан обычным параметром функции. Кроме того, его тип зависит от квалификаторов метода: внутри обычного метода это указатель на изменяемый объект, а внутри `const`-метода — указатель на константный объект.

Метод можно объявить внутри класса, а определить снаружи через квалифицированное имя:

```cpp
class Counter {
    int value = 0;

public:
    void increment();
};

void Counter::increment() {
    ++value;
}
```

`Counter::increment` означает, что функция `increment` принадлежит области класса `Counter`. Она остаётся методом и сохраняет доступ к его закрытым полям.

Определение метода внутри тела класса обычно неявно является `inline`. Это позволяет поместить его в заголовочный файл без нарушения ODR, если все определения эквивалентны. `inline` здесь не обещает фактическую подстановку тела в место вызова: решение об оптимизации принимает компилятор.

### Что можно объявлять внутри класса

Тело класса содержит объявления членов, а не произвольную последовательность выполняемых инструкций. В нём можно объявлять поля, методы, конструкторы, операторы, псевдонимы типов, перечисления, вложенные классы и некоторые другие сущности:

```cpp
class Container {
public:
    using Size = std::size_t;

    struct Node {
        int value;
    };
};
```

Внутри класса разрешён `using`: он часто задаёт псевдонимы типов или вводит члены базового класса. Но непосредственно выполнить выражение вроде `x += 1;` на уровне тела класса нельзя — выполняемый код должен находиться, например, внутри метода или инициализатора.

Вложенный класс является отдельным типом:

```cpp
Container::Node node{42};
```

Его можно одновременно объявить и использовать как тип поля:

```cpp
class C {
    struct S {
        char value;
    } field;
};
```

Класс разрешено объявить и внутри функции. Такой локальный класс виден только в своей области, однако на него действуют дополнительные ограничения языка.

### Размер, выравнивание и расположение полей

Размер объекта можно узнать через `sizeof`, а требуемое выравнивание — через `alignof`:

```cpp
struct Data {
    int number;
    double value;
};

std::cout << sizeof(Data) << '\n';
std::cout << alignof(Data) << '\n';
```

На распространённой платформе `int` занимает 4 байта и выравнивается по 4, а `double` занимает 8 байт и выравнивается по 8. Тогда после `number` компилятор может вставить 4 байта выравнивающего заполнения, и `sizeof(Data)` получится равен `16`.

Это пример, а не универсальное правило. Выравнивание не обязано совпадать с размером типа, и конкретные значения зависят от ABI и платформы. В конце объекта тоже может находиться заполнение, чтобы элементы массива таких объектов располагались с правильным выравниванием.

Компилятор сохраняет требуемый стандартом относительный порядок полей, но между ними могут быть промежутки. Из этого не следует, что объект можно произвольно читать как `int`, а затем как `double` по предполагаемому смещению. Доступ к объекту через несовместимый тип, нарушение выравнивания или выход за границы может привести к UB. Для работы с представлением объекта существуют специальные правила и средства вроде `offsetof` для подходящих standard-layout-типов, `std::memcpy` и `std::bit_cast`.

## §3.2. Модификаторы доступа

Класс обычно разделяет открытый интерфейс и внутреннюю реализацию. Для этого используются модификаторы доступа:

- `public` — член доступен обычному внешнему коду;
- `private` — член доступен самому классу и его друзьям;
- `protected` — доступен также в определённых контекстах наследования.

```cpp
class BankAccount {
public:
    void deposit(int amount) {
        if (amount > 0) {
            balance += amount;
        }
    }

    int get_balance() const {
        return balance;
    }

private:
    int balance = 0;
};
```

Внешний код может вызвать `deposit`, но не может напрямую записать произвольное значение в `balance`:

```cpp
BankAccount account;
account.deposit(100);

// account.balance = -1000; // ошибка компиляции: balance — private
```

Компилятор считает, что закрытый член сделан закрытым намеренно. Поэтому он не разрешает обращаться к нему через обычный внешний код, даже если программист знает имя поля и уверен, что запись ему сейчас удобна. Все изменения должны проходить через интерфейс, который может проверять условия и сохранять корректное состояние объекта.

`private` не является механизмом шифрования или защитой от чтения памяти другим процессом. Это правило языка, проверяемое компилятором. Его задача — не скрыть байты физически, а не позволить обычному коду зависеть от внутреннего устройства класса и нарушать его инварианты.

У `class` доступ по умолчанию закрытый:

```cpp
class C {
    int value; // private
};
```

У `struct` — открытый:

```cpp
struct S {
    int value; // public
};
```

Секции доступа можно повторять и располагать в любом порядке:

```cpp
class Example {
public:
    void first();

private:
    int value = 0;

public:
    void second();
};
```

Доступ предоставляется не отдельному объекту, а функциям класса. Поэтому метод одного объекта может читать закрытые поля другого объекта того же класса:

```cpp
class Number {
    int value = 0;

public:
    bool equals(const Number& other) const {
        return value == other.value;
    }
};
```

Метод, определённый снаружи как `Number::equals`, обладает теми же правами, что и метод с телом внутри класса.

`reinterpret_cast` не делает закрытый член доступным по правилам C++. Попытка угадать смещение поля и прочитать его через другой тип зависит от размещения объекта и может нарушать правила времени жизни, типов и выравнивания. Даже если конкретный эксперимент «работает», это не превращает его в корректный переносимый доступ к `private`.

## §3.3. Друзья класса

Иногда внешней функции нужен доступ к закрытому представлению класса. Её можно явно объявить другом:

```cpp
class Box {
    int value = 5;

    friend int read(const Box& box);
};

int read(const Box& box) {
    return box.value;
}
```

`read` получает доступ к `private` и `protected` членам `Box`, но не становится методом. У неё нет указателя `this`, и вызывается она как обычная функция:

```cpp
Box box;
std::cout << read(box) << '\n';
```

> Вывод: `5`.

Друга можно сразу определить внутри класса:

```cpp
class Box {
    int value = 5;

    friend int read(const Box& box) {
        return box.value;
    }
};
```

Такая функция всё равно не является членом. Часто она находится при поиске, связанном с типами аргументов (ADL), поэтому вызов `read(box)` работает. Обычный поиск функции без подходящего аргумента может вести себя иначе, чем поиск метода класса.

Другом может быть другой класс:

```cpp
class Inspector;

class Box {
    friend class Inspector;
    int value = 5;
};
```

Методы `Inspector` смогут обращаться к закрытым членам `Box`.

Дружба предоставляется явно и не распространяется автоматически:

- если `A` — друг `B`, то `B` не становится другом `A`;
- друзья друзей не получают доступ;
- дружба не наследуется производными классами.

`friend` полезен для тесно связанных операций, например операторов ввода и вывода, но чрезмерное количество друзей усиливает связанность и ослабляет границу интерфейса класса.

## §3.4. Конструкторы и деструкторы

### §3.4.1. Конструкторы

Конструктор — специальная функция-член, которая участвует в создании объекта. Его имя совпадает с именем класса, а возвращаемый тип не указывается даже как `void`.

```cpp
class Complex {
    double real = 0.0;

public:
    Complex(double value) {
        real = value;
    }
};
```

Сначала поле `real` инициализируется значением `0.0`, и только затем выполняется тело конструктора, где ему присваивается `value`. Инициализация и последующее присваивание — разные операции.

Поле лучше сразу инициализировать в списке инициализации членов:

```cpp
class Complex {
    double real;

public:
    Complex(double value)
        : real(value) {}
};
```

Теперь `real` сразу создаётся с нужным значением. Для фундаментального типа разница обычно невелика, но для сложного объекта второй вариант избегает создания одного состояния с последующим присваиванием другого. Для ссылок и `const`-полей список инициализации обязателен, потому что их нельзя оставить без значения, а затем переназначить.

Поля инициализируются в порядке объявления в классе, а не в порядке списка:

```cpp
class Example {
    int first;
    int second;

public:
    Example(int value)
        : second(value), first(second) {}
};
```

Несмотря на порядок записи, сначала инициализируется `first`. В этот момент `second` ещё не инициализирован, поэтому чтение его значения недопустимо. Компиляторы обычно предупреждают о несовпадении порядка. Надёжнее записывать инициализаторы в порядке объявления и не создавать между ними опасных зависимостей.

Конструктор можно вызвать разными формами инициализации:

```cpp
Complex first(1.0);   // прямая инициализация
Complex second{2.0};  // прямая инициализация списком
Complex third = 3.0;  // копирующая инициализация
Complex fourth = {4.0};
```

Если конструктор из одного аргумента не помечен `explicit`, он также задаёт неявное преобразование из типа аргумента в тип класса. Разные формы инициализации по-разному относятся к `explicit` и `std::initializer_list`; подробнее это рассматривается ниже.

#### Конструктор по умолчанию

Конструктор по умолчанию можно вызвать без аргументов:

```cpp
class Counter {
public:
    Counter() = default;
};

Counter counter;
```

Если пользователь не объявил ни одного конструктора, компилятор обычно неявно объявляет конструктор по умолчанию. Как только пользователь объявляет собственный конструктор, автоматическое объявление конструктора без аргументов обычно прекращается:

```cpp
class Number {
public:
    Number(int value) {}
};

// Number number; // ошибка: конструктора без аргументов нет
```

Его можно запросить явно:

```cpp
Number() = default;
```

Но `= default` не гарантирует, что конструктор можно будет вызвать. Если поле-ссылка не получает объект или поле некоторого типа само невозможно сконструировать без аргументов, сгенерированный конструктор будет определён как удалённый:

```cpp
class ReferenceHolder {
    int& reference;

public:
    ReferenceHolder() = default; // фактически удалён
};
```

Компилятор не может придумать, с каким объектом связать `reference`.

#### Инициализация списком и `std::initializer_list`

Конструктор может принимать `std::initializer_list<T>`:

```cpp
class String {
public:
    String(std::initializer_list<char> characters) {
        for (char character : characters) {
            // Добавить character в строку.
        }
    }
};

String text{'a', 'b', 'c'};
```

`std::initializer_list` предоставляет `begin`, `end` и `size`. Его элементы доступны как константные значения: перемещать их как обычные изменяемые объекты нельзя.

При инициализации фигурными скобками подходящие конструкторы с `std::initializer_list` получают особый приоритет. Но это не означает, что наличие хотя бы одного такого конструктора заставляет абсолютно любой набор `{...}` выбрать его: перегрузка всё равно должна подходить.

Из-за приоритета две похожие записи способны означать разное:

```cpp
std::vector<int> first(3, 7); // три элемента со значением 7
std::vector<int> second{3, 7}; // два элемента: 3 и 7
```

Кроме того, инициализация списком запрещает многие сужающие преобразования:

```cpp
// int value{3.5}; // ошибка компиляции
```

#### Конструктор копирования

Конструктор копирования создаёт новый объект из существующего объекта того же типа:

```cpp
class String {
    char* data = nullptr;
    std::size_t size = 0;
    std::size_t capacity = 0;

public:
    String(const String& other)
        : data(new char[other.capacity]),
          size(other.size),
          capacity(other.capacity) {
        std::memcpy(data, other.data, size + 1);
    }
};
```

Пример предполагает, что `capacity >= size + 1`, `other.data` указывает на корректный массив и после символов строки хранится завершающий ноль. Новый объект выделяет собственный массив и копирует содержимое. Поэтому изменение или уничтожение одной строки не затрагивает массив другой.

Аргумент принимается по ссылке. Передача `String other` по значению потребовала бы сначала скопировать аргумент тем же конструктором, что снова потребовало бы копирования, и так без конца. Ссылка обычно константная, потому что копирование не должно менять источник и должно работать с `const String`.

`std::memcpy` подходит для непересекающихся областей байтов. Для пересекающихся областей используют `std::memmove`. Здесь массивы разных объектов не пересекаются, если класс корректно реализует раздельное владение.

Компилятор может неявно объявить конструктор копирования, но он не «гарантированно работает» для любого класса: конструктор может оказаться удалённым, например из-за некопируемого поля. Автоматическая реализация копирует каждое поле. Для владеющего сырого указателя это означает копирование адреса, а не массива, после чего два объекта ошибочно считают себя владельцами одной памяти.

Copy-on-write хранит общие данные у нескольких объектов до первой попытки изменения. Это не получается простым сохранением автоматически сгенерированного копирования: нужны учёт общего владения, корректная синхронизация и отделение данных перед записью. Для обычного класса это заметно сложнее глубокого копирования или использования готового умного указателя.

#### Делегирующие и удалённые конструкторы

Один конструктор может делегировать создание объекта другому конструктору того же класса:

```cpp
class Complex {
    double real;
    double imaginary;

public:
    Complex(double real, double imaginary)
        : real(real), imaginary(imaginary) {}

    Complex()
        : Complex(0.0, 0.0) {}
};
```

Сначала полностью выполняется целевой конструктор, затем тело делегирующего. В списке делегирующего конструктора нельзя одновременно перечислить другие поля: их уже инициализирует целевой конструктор.

Запись `Complex();` или попытка вызвать `this->Complex()` внутри тела не переинициализирует текущий объект. Первая создаст отдельный временный объект, а вторая вообще не является допустимым синтаксисом вызова конструктора для `this`.

Нежелательную перегрузку можно удалить:

```cpp
class File {
public:
    File(const char* path);
    File(int) = delete;
};
```

Удалённая функция участвует в выборе перегрузки. Если она оказывается лучшим кандидатом, вызов завершается ошибкой компиляции. Это позволяет явно запретить конкретные преобразования, а не надеяться, что подходящей функции случайно не найдётся.

### §3.4.2. Деструкторы

Деструктор завершает время жизни объекта и освобождает принадлежащие ему ресурсы. Его имя состоит из `~` и имени класса:

```cpp
class Buffer {
    char* data;

public:
    explicit Buffer(std::size_t size)
        : data(new char[size]) {}

    ~Buffer() {
        delete[] data;
    }
};
```

Когда объект `Buffer` уничтожается, деструктор освобождает принадлежащий ему массив. Это пример RAII: ресурс приобретается при создании объекта и освобождается автоматически вместе с ним.

Порядок уничтожения является обратным порядку завершения создания:

```cpp
void f() {
    Buffer first(10);
    Buffer second(20);
} // сначала second, затем first
```

Сначала выполняется тело деструктора самого класса. В это время его поля ещё существуют, поэтому к ним можно обращаться. После тела поля автоматически уничтожаются в порядке, обратном их объявлению, а затем уничтожаются базовые подобъекты.

Момент уничтожения зависит от длительности хранения:

- автоматические объекты обычно уничтожаются при выходе из области, в том числе при раскрутке стека из-за исключения;
- динамический объект уничтожается соответствующим `delete`;
- статические объекты уничтожаются при завершении программы, обычно в порядке, обратном завершению их инициализации.

Порядок между статическими объектами разных единиц трансляции может быть сложным и не всегда заранее известным. Поэтому один глобальный объект не должен бездумно обращаться из деструктора к другому глобальному объекту, который уже мог быть уничтожен.

В C++ нет обязательного сборщика мусора, который определяет недостижимые объекты. Вместо этого время освобождения обычно выражают через области видимости и владельцев ресурсов.

Для каждого успешно созданного объекта его время жизни должно корректно завершиться один раз. Повторный `delete` или повторный вызов деструктора без специального повторного создания объекта приводит к ошибке. В низкоуровневом коде существуют явный вызов деструктора и placement `new`, но там программист самостоятельно обязан соблюдать правила времени жизни.

Деструкторы обычно не должны выпускать исключения. Если исключение покидает деструктор во время обработки другого исключения, программа завершится через `std::terminate`.

## §3.5. Оператор присваивания

Конструктор копирования создаёт новый объект, а оператор копирующего присваивания меняет уже существующий:

```cpp
String first = second; // создание: конструктор копирования

String third;
third = second;        // изменение: оператор присваивания
```

Компилятор может автоматически объявить копирующее присваивание, которое присваивает поля по отдельности. Для класса с владеющим сырым указателем этого недостаточно: старый ресурс левого объекта нужно освободить, а данные правого — корректно скопировать.

Один из вариантов реализации — copy-and-swap:

```cpp
String& operator=(const String& other) {
    String copy(other);
    swap(copy);
    return *this;
}
```

Последовательность действий:

1. Из `other` создаётся независимая копия.
2. Содержимое копии обменивается с текущим объектом.
3. Функция возвращает ссылку на текущий объект.
4. При выходе локальная `copy` уничтожает прежнее содержимое текущего объекта.

Если создание копии бросит исключение, исходный объект ещё не изменён. Поэтому при корректном `swap` идиома естественным образом даёт строгую гарантию исключений.

Самоприсваивание `value = value` тоже работает: сначала создаётся отдельная копия, и только потом происходит обмен.

Возвращается именно `String&`, а не `String`, чтобы не создавать лишнюю копию и поддерживать цепочки:

```cpp
a = b = c;
```

Сначала выполняется `b = c`, возвращается сам `b`, затем его значение присваивается `a`.

Вариант с параметром по значению объединяет копирование и перемещение:

```cpp
String& operator=(String other) {
    swap(other);
    return *this;
}
```

Для lvalue-аргумента `other` копируется, а для временного объекта может перемещаться. Этот вариант короче, но не всегда оптимален для конкретного класса; выбор зависит от стоимости операций и требуемых гарантий.

### §3.5.1. Правило трёх, пяти и нуля

Если класс вручную управляет ресурсом и ему понадобился собственный деструктор, конструктор копирования или оператор копирующего присваивания, обычно нужно продумать все три операции. Это **правило трёх**.

Причина не в синтаксическом требовании компилятора, а в общей ответственности за владение. Если деструктор удаляет сырой указатель, автоматическое копирование этого указателя почти наверняка приведёт к совместному владению без учёта и двойному освобождению.

Начиная с C++11 у класса также есть перемещающий конструктор и перемещающее присваивание. Для ресурсо-владеющего типа получается **правило пяти**:

1. деструктор;
2. конструктор копирования;
3. копирующее присваивание;
4. конструктор перемещения;
5. перемещающее присваивание.

Пользовательское объявление некоторых специальных функций влияет на автоматическое объявление других, поэтому нельзя рассчитывать, что компилятор всегда сгенерирует оптимальное перемещение после добавления деструктора.

Предпочтительнее **правило нуля**: хранить ресурсы в типах, которые уже правильно реализуют владение:

```cpp
class Buffer {
    std::vector<char> data;
};
```

Тогда копирование, перемещение и уничтожение `Buffer` естественно составляются из соответствующих операций `std::vector`, и вручную писать пять специальных функций обычно не требуется.

## §3.6. Константные и статические члены, `explicit`

### Константные методы

Неконстантный метод потенциально может менять объект, поэтому вызвать его у `const`-объекта нельзя:

```cpp
class Counter {
    int value = 0;

public:
    int get() const {
        return value;
    }

    void increment() {
        ++value;
    }
};

const Counter counter;
counter.get();
// counter.increment(); // ошибка компиляции
```

Квалификатор `const` после списка параметров относится к объекту вызова:

```cpp
int get() const;
```

Внутри такого метода `this` ведёт себя как указатель на константный объект. Нельзя менять обычные поля или вызывать для них операции, требующие неконстантного объекта.

Утверждение «у константного объекта просто отсутствует часть методов» удобно как первое приближение, но точнее сказать, что набор кандидатов при вызове учитывает cv-квалификацию объекта. Методы можно перегружать по `const`:

```cpp
class String {
public:
    char& operator[](std::size_t index);
    const char& operator[](std::size_t index) const;
};
```

Обычный объект получает изменяемую ссылку, а константный — только ссылку для чтения:

```cpp
String text = "abcd";
const String& const_text = text;

const char& character = const_text[0];
text[0] = 'b';

assert(character == 'b');
```

`const_text` не создаёт копию и не делает исходный объект навсегда константным. Он лишь запрещает изменение через эту ссылку. Поэтому изменение через `text` допустимо, а `character`, ссылающийся на тот же элемент, увидит новое значение.

### `mutable` и логическая константность

Поле `mutable` разрешено изменять в `const`-методе:

```cpp
class Value {
    int value = 0;
    mutable bool cache_valid = false;

public:
    int get() const {
        cache_valid = true;
        return value;
    }
};
```

Обычно `mutable` применяют к служебному состоянию, которое не меняет наблюдаемое значение объекта: кэшу, счётчику обращений или мьютексу. Это выражает логическую, а не побитовую константность.

`mutable` не решает проблему потокобезопасности. Если несколько потоков одновременно меняют кэш без синхронизации, квалификатор `const` не предотвращает гонку данных.

### Статические поля и методы

Статический член относится ко всему классу, а не к отдельному объекту:

```cpp
class Object {
    inline static std::size_t count = 0;

public:
    Object() {
        ++count;
    }

    static std::size_t get_count() {
        return count;
    }
};
```

У всех объектов одна переменная `Object::count`. Статический метод не имеет `this`, поэтому не может обратиться к нестатическому полю без конкретного объекта.

Начиная с C++17 `inline static`-поле можно определить и инициализировать внутри класса. Поэтому общий запрет на инициализацию неконстантного статического поля внутри класса неверен. До C++17 обычному статическому полю, как правило, требовалось отдельное определение в `.cpp`:

```cpp
class Object {
    static std::size_t count;
};

std::size_t Object::count = 0;
```

Для `constexpr`, `const` целочисленных членов и разных версий стандарта существуют дополнительные правила определения и ODR-использования.

### `explicit`

Конструктор из одного аргумента может участвовать в неявном преобразовании:

```cpp
class Complex {
public:
    Complex(double real) {}
};

void print(Complex value);

print(2.0); // double неявно превращается в Complex
```

Если такое преобразование нежелательно, конструктор помечают `explicit`:

```cpp
explicit Complex(double real) {}
```

Теперь неявный вызов `print(2.0)` запрещён, но явное создание остаётся доступным:

```cpp
print(Complex{2.0});
```

`explicit` влияет на формы инициализации по-разному. Прямая инициализация рассматривает такой конструктор, а копирующая обычно нет:

```cpp
Complex first{1.0};
// Complex second = 1.0; // ошибка для explicit-конструктора
```

Операторы преобразования задают переход из класса в другой тип:

```cpp
class Complex {
public:
    explicit operator double() const;
};
```

Операторы преобразования могут быть `explicit` начиная с C++11, но язык не требует помечать так каждый оператор. Решение зависит от того, должно ли преобразование происходить незаметно. `explicit operator bool` имеет отдельное удобное поведение в контекстах условий, например в `if`.

### Пользовательские литералы

Начиная с C++11 можно объявлять пользовательские литеральные операторы:

```cpp
constexpr long double operator""_deg(long double degrees) {
    return degrees * 3.14159265358979323846L / 180.0L;
}

long double angle = 90.0_deg;
```

Пользовательский суффикс должен начинаться с подчёркивания. Допустимые параметры зависят от вида литерала: например, `unsigned long long` используется для обработанного целого литерала, `long double` — для вещественного, а строковые формы могут принимать указатель вместе с длиной. Одного варианта `const char*` недостаточно, чтобы описать все виды пользовательских литералов.

## §3.7. Перегрузка операторов

Перегрузка позволяет определить смысл существующего оператора для пользовательского типа. Она не создаёт новый знак и не меняет грамматику языка.

Нельзя изменить:

- приоритет и ассоциативность оператора;
- число его операндов;
- встроенное поведение для двух фундаментальных типов;
- общий порядок вычисления операндов, если язык не задаёт его отдельно.

Хотя бы один операнд перегруженного оператора должен иметь классический или перечислимый тип. Некоторые операторы перегружать нельзя, в том числе `.`, `.*`, `::`, `?:` и `sizeof`.

Рассмотрим тип комплексного числа:

```cpp
class Complex {
public:
    double real = 0.0;
    double imaginary = 0.0;

    Complex(double real)
        : real(real) {}

    Complex(double real, double imaginary)
        : real(real), imaginary(imaginary) {}
};
```

Поля открыты только для краткости примеров. В полноценном классе можно оставить их закрытыми и предоставить методам или друзьям контролируемый доступ.

### Сложение: метод или внешняя функция

Оператор как метод получает левый операнд через `this`:

```cpp
Complex operator+(const Complex& other) const {
    return Complex{
        real + other.real,
        imaginary + other.imaginary
    };
}
```

Такая версия позволяет написать `complex + 2.0`: правый `double` может преобразоваться в `Complex`. Но выражение `2.0 + complex` ищет оператор для левого `double`, у которого нет методов класса `Complex`.

Внешняя функция обрабатывает оба операнда одинаково:

```cpp
Complex operator+(const Complex& left, const Complex& right) {
    return Complex{
        left.real + right.real,
        left.imaginary + right.imaginary
    };
}
```

Теперь допустимы преобразования как первого, так и второго аргумента. Если поля закрыты, функцию можно сделать другом или реализовать через открытый интерфейс.

Определять одновременно эквивалентные член и внешнюю функцию без необходимости не следует: это может привести к неоднозначному выбору перегрузки.

### Составное присваивание и обычное сложение

Наивная реализация `+=` через `+` создаёт временный объект и затем присваивает его:

```cpp
Complex& operator+=(const Complex& other) {
    *this = *this + other;
    return *this;
}
```

Эффективнее изменить поля напрямую:

```cpp
Complex& operator+=(const Complex& other) {
    real += other.real;
    imaginary += other.imaginary;
    return *this;
}
```

После этого `+` удобно реализовать через `+=`:

```cpp
Complex operator+(Complex left, const Complex& right) {
    left += right;
    return left;
}
```

Левый операнд передаётся по значению и служит готовой копией результата. Для временного левого операнда компилятор может использовать перемещение. Возврат локального объекта также допускает устранение копирования.

Для обычного, не ограниченного квалификаторами оператора присваивания может скомпилироваться странное выражение:

```cpp
a + b = c;
```

`a + b` создаёт временный объект, и присваивание меняет только его, а не `a` или `b`. Чтобы запретить присваивание временным объектам, оператор можно разрешить только для lvalue:

```cpp
Complex& operator=(const Complex& other) &;
```

Завершающий `&` — ref-квалификатор метода. Он означает, что `this` должен соответствовать lvalue-объекту.

### Ввод и вывод

В выражении `std::cout << value` левым операндом является поток, а не пользовательский объект. Поэтому оператор обычно определяют внешней функцией:

```cpp
std::ostream& operator<<(std::ostream& output, const Complex& value) {
    return output
        << value.real
        << " + "
        << value.imaginary
        << 'i';
}
```

Поток передаётся по неконстантной ссылке, потому что вывод меняет его состояние. Возвращается тот же поток, чтобы работали цепочки:

```cpp
std::cout << first << ' ' << second << '\n';
```

Если данные закрыты, оператор использует открытые методы или объявляется другом. Аналогично строится `operator>>`, но он должен отдельно решать, что делать при неверном формате ввода и в каком состоянии оставить объект.

### Сравнения

Можно задать лексикографический порядок: сначала сравнить действительную часть, а при равенстве — мнимую:

```cpp
bool operator<(const Complex& left, const Complex& right) {
    return left.real < right.real
        || (left.real == right.real
            && left.imaginary < right.imaginary);
}
```

Это выбранный программистом порядок, а не естественное математическое сравнение комплексных чисел.

До C++20 наличие `<` само по себе не создаёт остальные операторы. Их можно выразить вручную:

```cpp
bool operator>(const Complex& left, const Complex& right) {
    return right < left;
}

bool operator<=(const Complex& left, const Complex& right) {
    return !(right < left);
}

bool operator>=(const Complex& left, const Complex& right) {
    return !(left < right);
}

bool operator==(const Complex& left, const Complex& right) {
    return left.real == right.real
        && left.imaginary == right.imaginary;
}
```

`std::map` по умолчанию использует `std::less`, который обычно опирается на `<`, и ожидает строгий слабый порядок. Если сравнение нарушает его свойства, контейнер не сможет корректно организовать элементы.

Для `double` существует значение NaN, которое не меньше, не больше и не равно даже самому себе. Поэтому формулы вроде `!(a < b) && !(b < a)` описывают эквивалентность относительно порядка, но не обязаны совпадать с покомпонентным `==`. Компаратор для ассоциативного контейнера с NaN требует отдельного продуманного решения.

### Трёхстороннее сравнение

Начиная с C++20 оператор `<=>` может выразить порядок одним сравнением:

```cpp
class Point {
public:
    int x;
    int y;

    auto operator<=>(const Point&) const = default;
};
```

Defaulted-оператор сравнивает поля лексикографически в порядке объявления. На его основе компилятор может переписать выражения `<`, `>`, `<=` и `>=`. Для defaulted `<=>` также может быть неявно объявлен подходящий `==`.

Категория результата зависит от полей:

- `std::strong_ordering` подходит для полного порядка, где эквивалентные значения взаимозаменяемы в отношении сравнения;
- `std::weak_ordering` допускает эквивалентные, но различимые значения;
- `std::partial_ordering` допускает несравнимые значения.

Для класса с полями `double` defaulted `<=>` возвращает `std::partial_ordering`, потому что NaN несравним с обычными числами:

```cpp
auto operator<=>(const Complex&) const = default;
```

Для такого defaulted-оператора нельзя явно указать `std::weak_ordering`: категория должна учитывать возможность несравнимого результата.

Если `<=>` написан вручную, обычный `operator==` автоматически из его тела не создаётся. Его нужно определить отдельно, если он требуется. Механизм переписанных кандидатов умеет рассматривать операнды в обоих направлениях в предусмотренных стандартом случаях, но не гарантирует автоматически все мыслимые сравнения для любых смешанных типов.

### Инкремент

Префиксный и постфиксный инкременты отличаются сигнатурой:

```cpp
Complex& operator++() {
    ++real;
    ++imaginary;
    return *this;
}

Complex operator++(int) {
    Complex old = *this;
    ++(*this);
    return old;
}
```

Префиксная версия меняет объект и возвращает его по ссылке. Постфиксная должна вернуть прежнее значение, поэтому сохраняет копию. Параметр `int` служит меткой, отличающей постфиксную перегрузку; при обычном `value++` его значение не используется.

Постфиксную версию удобно реализовать через префиксную, чтобы сама логика изменения находилась в одном месте.

### Оператор вызова функции

Если класс определяет `operator()`, его объект можно вызывать как функцию:

```cpp
struct Greater {
    bool operator()(int left, int right) const {
        return left > right;
    }
};

Greater greater;
bool result = greater(3, 2);
```

`result == true`. Такой объект называют функциональным объектом, или функтором. В отличие от обычной функции, он может хранить состояние в полях и настраиваться при создании.

## §3.8. Указатели на члены

Указатель на член не указывает на поле конкретного объекта. Он описывает, какой член нужно выбрать, когда объект будет предоставлен позже.

```cpp
struct S {
    int value = 0;

    void increment() {
        ++value;
    }

    int get() const {
        return value;
    }
};

int S::* field = &S::value;
void (S::* method)() = &S::increment;
```

`int S::*` — тип указателя на поле типа `int` в классе `S`. Это не `int*`: без объекта `S` получить конкретный `int` невозможно.

Для объекта используется оператор `.*`:

```cpp
S object;

object.*field = 3;
(object.*method)();
```

После присваивания `object.value == 3`, а после вызова метода — `4`. Скобки вокруг `object.*method` нужны из-за приоритета операций.

Для указателя на объект используется `->*`:

```cpp
S* pointer = &object;

pointer->*field = 10;
(pointer->*method)();
```

После этого `object.value == 11`.

Указатель на поле можно мысленно представить как описание смещения, но его реальное представление не обязано быть обычным целым смещением. Оно зависит от ABI, наследования и вида члена. Преобразовывать такой указатель в число и вручную прибавлять его к адресу объекта нельзя.

Тип указателя на метод включает параметры и квалификаторы метода:

```cpp
int (S::* getter)() const = &S::get;
```

Указатель на константный метод и указатель на неконстантный метод имеют разные типы.

Указатели на члены могут быть нулевыми. Для универсального вызова обычных функций, методов и указателей на члены стандартная библиотека предоставляет `std::invoke`.

## §3.9. Перечисления

Перечисление создаёт отдельный тип с набором именованных целочисленных констант. Оно удобно для состояний, режимов и вариантов, которым не хочется присваивать безымянные числа.

### Обычное перечисление

```cpp
enum Color {
    Red,
    Green,
    Blue
};
```

Если значения не указаны, первый элемент получает `0`, а каждый следующий — предыдущее значение плюс один:

```cpp
Color color = Red;
int value = Green; // value == 1
```

Обычный unscoped `enum` неявно преобразуется в подходящий целочисленный тип. Обратное неявное преобразование запрещено:

```cpp
// Color color = 1; // ошибка компиляции
Color color = static_cast<Color>(1);
```

Значения можно задавать явно и повторять:

```cpp
enum Status {
    Ok = 200,
    Created = 201,
    Success = 200,
    Error = 500
};
```

Если после явно заданного элемента число не указано, используется предыдущее плюс один:

```cpp
enum Number {
    First = 5,
    Second,    // 6
    Third = 10,
    Fourth     // 11
};
```

Переменная перечислимого типа не обязана во всех низкоуровневых ситуациях содержать только одно из именованных значений. Имена задают удобные константы, но допустимый диапазон представления связан с базовым типом и правилами перечислений. Поэтому код всё равно должен продумывать обработку неожиданных значений, особенно после приведения, чтения данных или взаимодействия с внешним API.

Размер перечисления не обязан совпадать с `sizeof(int)`. Компилятор выбирает подходящий базовый целочисленный тип по правилам языка, если он не указан явно.

### `enum class`

Scoped-перечисление не выносит имена элементов в окружающую область и не преобразуется неявно в целое:

```cpp
enum class Color {
    Red,
    Green,
    Blue
};

Color color = Color::Red;

// int value = Color::Green; // ошибка компиляции
int value = static_cast<int>(Color::Green);
```

Это уменьшает конфликты имён и не позволяет случайно смешивать перечисление с числами или другим перечислением.

Базовый тип можно указать после двоеточия:

```cpp
enum class Color : unsigned char {
    Red,
    Green,
    Blue
};
```

Двоеточие здесь не означает наследование. Оно задаёт underlying type — целочисленный тип, в котором представляются значения перечисления. Для `enum class` без явного указания базовым типом является `int`.

Начиная с C++20 имена scoped-перечисления можно локально ввести через `using enum`:

```cpp
using enum Color;
Color color = Red;
```

Это удобно в ограниченной области, например внутри функции или `switch`, но при большом количестве перечислений снова может привести к конфликтам имён.

Перечисление особенно удобно со `switch`:

```cpp
std::string_view to_string(Color color) {
    switch (color) {
        case Color::Red:
            return "red";
        case Color::Green:
            return "green";
        case Color::Blue:
            return "blue";
    }

    return "unknown";
}
```

Компилятор с включёнными предупреждениями может сообщить, что обработан не каждый именованный элемент. Но перечисление само по себе не гарантирует, что выполнение обязательно попадёт в один из перечисленных `case`, поэтому для данных из ненадёжного источника полезно иметь осознанную обработку неизвестного значения.
