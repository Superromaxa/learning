# Rocq/Coq: основы доказательств и функций

## 1. Контекст и цель

```coq
hAB : A -> B
hA  : A
==================
B
```

- Над чертой — доступные объекты и доказательства.
- Под чертой — текущая цель.
- `hA : A`: `hA` является доказательством proposition `A`.
- `hAB : A -> B`: `hAB` превращает доказательство `A` в доказательство `B`.

Пробел означает применение функции:

```coq
hAB hA : B
```

## 2. Импликация, `forall` и `move=>`

Если цель — импликация:

```coq
==================
A -> B
```

то `move=> hA` вводит её вход:

```coq
hA : A
==================
B
```

Мы не объявляем `A` истинным вообще. Мы строим функцию, которая при получении доказательства `A` должна вернуть доказательство `B`.

Стрелка ассоциируется вправо:

```coq
A -> B -> C = A -> (B -> C)
```

Поэтому `move=> hA hB` может ввести два последовательных аргумента.

Для `forall` вводится произвольный объект:

```coq
Lemma identity_prop : forall P : Prop, P -> P.
Proof.
  move=> P p.
  exact p.
Qed.
```

Здесь `P : Prop` означает, что `P` — proposition, а `p : P` — что `p` является его доказательством.

## 3. Как закончить простую цель

### `exact`

Передаёт готовое доказательство текущей цели:

```coq
hA : A
==================
A

exact hA.
```

Можно передать составное выражение:

```coq
exact (hAB hA).  (* если hAB : A -> B, hA : A, цель B *)
```

### `assumption`

Сам ищет в контексте готовое доказательство нужного типа. При `hA : A` и цели `A` работает как `exact hA`.

### `trivial`

Пробует автоматически решить очень простую цель. Для понимания доказательства обычно яснее писать `exact` или `assumption`.

## 4. `apply`: строим доказательство назад

```coq
hAB : A -> B
==================
B
```

После `apply hAB` получаем новую цель `A`. Rocq начал строить `hAB ?a`, где `?a` — внутреннее незаполненное место типа `A`. Вручную вопросительный знак обычно не пишут.

```coq
h : A -> B -> C
==================
C
```

Здесь `apply h` создаст цели `A` и `B`.

Но при:

```coq
h : (A -> B) -> C
==================
C
```

`apply h` создаст одну цель `A -> B`: единственный аргумент `h` сам является функцией.

Если конечный результат применяемого выражения не совпадает с целью, `apply` не сработает.

## 5. Несколько целей

Rocq работает с первой незакрытой целью, а после её завершения автоматически переходит к следующей:

```coq
split.
- exact hA.
- exact hB.
```

Маркеры `-`, `+`, `*` только отделяют ветки и уровни вложенности. Каждая ветка имеет собственный локальный контекст.

## 6. Конъюнкция `A /\ B`

Если конъюнкция находится в цели, `split` создаёт две цели — `A` и `B`. Нужно доказать обе:

```coq
Lemma make_conjunction : A -> B -> A /\ B.
Proof.
  move=> hA hB.
  split.
  - exact hA.
  - exact hB.
Qed.
```

Если конъюнкция является входом, её можно сразу разобрать:

```coq
move=> [hA hB].
```

Если она уже находится в контексте как `h : A /\ B`:

```coq
case: h => [hA hB].
```

В обоих случаях получаем `hA : A` и `hB : B`.

## 7. Дизъюнкция `A \/ B`

Если `h : A \/ B` находится в контексте, нужно рассмотреть оба возможных случая:

```coq
case: h => [hA | hB].
```

Получаются две независимые ветки: в первой доступно `hA : A`, во второй — `hB : B`.

Если `A \/ B` находится в цели:

- `left` выбирает левую сторону и оставляет цель `A`;
- `right` выбирает правую сторону и оставляет цель `B`.

```coq
Lemma swap_disjunction : A \/ B -> B \/ A.
Proof.
  move=> h.
  case: h => [hA | hB].
  - right. exact hA.
  - left.  exact hB.
Qed.
```

Тактики смотрят на внешнюю операцию цели. Например, для `(A \/ B) -> (C \/ D)` сначала нужен `move=>`; только после этого можно использовать `left` или `right`.

## 8. `False` и отрицание

`False` — proposition без способов построить доказательство. Поэтому `case: h`, где `h : False`, не создаёт ни одной ветки и закрывает текущую цель:

```coq
Lemma false_implies_anything : False -> A.
Proof.
  move=> h.
  case: h.
Qed.
```

Отрицание — это сокращение:

```coq
~ A = A -> False
```

Значит, `hNotA : ~A` — функция, превращающая доказательство `A` в `False`:

```coq
Lemma no_contradiction : ~ (A /\ ~ A).
Proof.
  move=> [hA hNotA].
  apply hNotA.
  exact hA.
Qed.
```

## 9. `Qed` и `Abort`

- `Qed.` проверяет завершённое доказательство и сохраняет лемму. При незакрытых целях он выдаст ошибку.
- `Abort.` прекращает доказательство и не сохраняет лемму.

## 10. Быстрый выбор тактики

| Внешняя форма цели | Типичный шаг |
|---|---|
| `A -> B` | `move=> hA` |
| `forall x : T, P` | `move=> x` |
| `A /\ B` | `split` |
| `A \/ B` | `left` или `right` |
| Есть готовое доказательство | `exact ...` или `assumption` |
| Есть функция с нужным результатом | `apply ...` |

Если составное доказательство находится в контексте, его обычно разбирают с помощью `case` или шаблона в `move=>`.

## 11. Типы функций

В стандартном Rocq натуральные числа обычно имеют тип `nat`; здесь `num` — условное название числового типа.

```coq
num -> num
```

— функция, принимающая число и возвращающая число.

Безымянная функция записывается через `fun`:

```coq
fun x => x
```

Стрелка в типе ассоциируется вправо, а применение — влево:

```coq
num -> num -> num = num -> (num -> num)
f x y                 = (f x) y
```

Тип:

```coq
num -> (num -> num) -> num
```

описывает функцию, принимающую число `x`, затем функцию `f : num -> num`, и возвращающую число. Примеры:

```coq
fun x f => x
fun x f => f x
fun x f => f (f x)
```

Все три выражения имеют одинаковый тип, но по-разному используют аргументы.

## Главная идея

Доказательство в Rocq — обычное типизированное выражение:

- proposition играет роль типа;
- доказательство является значением этого типа;
- импликация является типом функции;
- тактики постепенно строят выражение, которое затем проверяет ядро Rocq.
